# Explicit filesystem tools

C2.1 adds `fs.read`, `fs.list` and `fs.search`; C2.2 adds `fs.write` and `fs.edit` to the existing model/tool lifecycle. Hosts opt in with `ToolRegistry::with_filesystem_reads()` or `ToolRegistry::configured`; an empty registry still grants nothing. CLI and ACP enable reads by default. `--no-shell` removes shell, `--no-filesystem` removes filesystem tools, and both select text-only execution. Use `--allow-write` or `ToolRegistry::configured_with_writes` to explicitly enable mutations. Provider names are `fs_read`, `fs_list`, `fs_search`, `fs_write`, `fs_edit`; native names and call IDs remain unchanged.

The implemented read contracts and defaults are in [the C2 specification](project/contracts/c2-single-agent.md#read-list-and-search). C2.3 adds the shared task envelope and C2.4 completes accounting and policy. `--policy PATH` supports `tools`, `executables`, `read_roots` and `write_roots`. Policies are bounded JSON with deny precedence and stable rule IDs. Tool and executable values match exactly (no wildcard interpretation); executable policy checks only the actual `/bin/sh` launcher, not command contents or descendants. Root rules match directory components. Explicit host denial overrides capabilities and write opt-in. Static policy is not process containment.

The runtime opens a canonical workspace directory handle at admission. Workers use directory-relative no-follow operations and reject symlinks, parent traversal, special-file reads and paths outside that root. Listing exposes link names/types without resolving them; search skips links and binary files. Hosts own filesystem isolation and interference by other processes. No syscall-latency guarantee is made for arbitrary mounted filesystems.

Reads take bounded UTF-8 snapshots and hash the same bytes with SHA-256. Pages never split a codepoint. Lists are direct, sorted and stateless; search is recursive, case-sensitive and literal, with explicit truncation at the requested match limit. File/entry/depth/scan work limits stop the run rather than masquerading as complete results. Retained matches are counted incrementally; the complete serialized result is checked without allocating another result-sized JSON buffer.

Requested `max_output_bytes` must be at least 1,024, matching the host result minimum so errors and metadata always have capacity. This C2.1 clarification narrows C2.0's positive-integer request rule; it does not change the generous 8 MiB default. Workers read at most one additional byte to detect a breached byte cap, checking while reading rather than trusting initial metadata.

Each tool has the existing native start/finish pair and a run-child OTel span, without a shell-start event. Redacted traces retain counts, truncation/error metadata and policy decisions; paths, text, queries, matches and revisions stay out of default native traces and all OTel spans. Explicit native capture remains independent of live ACP results. Recoverable filesystem errors reach the next model request; policy, argument, cancellation, timeout and hard-limit failures remain terminal.

Filesystem work runs on Tokio's blocking pool and checks cancellation/deadlines between bounded operations. The runtime awaits the worker before finishing the tool. No worker is detached to make a cancellation appear fast. The pool and compiled registry remain reusable across independent ACP tasks, with separate workspace handles and task state.

The native contract revision is `c2.2`; the existing `pablo/v1` extension schema accepts historical `c1.2`/`c2.1` and the new revision. Its rule union and limit enumeration include configured rules, symlink denial and filesystem work exhaustion. The reference client understands these outcomes. No upstream ACP or OTel convention pin changed.

## Revision-checked mutations

`fs.write` requires `path`, UTF-8 `text` and `expected_revision`: null means atomic create-only, while SHA-256 means replace only after checking current text. `fs.edit` requires a SHA-256 revision, nonempty `old_text` and `new_text`; exactly one literal match is replaced. Existing parents and explicit write authority are required. Replacements also require read authority. Native/ACP results preserve closed conflicts/errors without exposing raw OS messages.

A private file is written in the target directory, ordinary permission bits are applied, and revision/policy/cancellation are rechecked before atomic installation. Create uses no-replace hard-link installation followed by temporary-name cleanup; replace uses same-directory rename. Ordinary permission bits are preserved; special bits are cleared; new files are 0600. Ownership/ACLs/xattrs/hard-link identity and crash durability are not promised. Tools remain sequential per run; hosts must isolate concurrent runs/external writers if they need more than optimistic conflict detection.

The complete result is admitted before creating a temporary file, so an output cap cannot hide a successful mutation. Before commit, failure/cancellation leaves the target intact and cleanup is awaited. After commit, the tool reports `committed:true` even if the run then settles cancelled. Cleanup failure retains committed truth and becomes an explicit tool-cleanup failure. Tests include controlled external-writer races, injected write/rename/cleanup failures and a concurrent reader observing only complete old/new bytes.
