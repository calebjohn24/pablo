# C3.6 OpenRouter adapter

Frozen before implementation, based on the official OpenRouter Chat Completions documentation checked 2026-09-10. Extends the [provider selection contract](c3-provider-selection.md); configuration schema v1/revision c3.5 is unchanged because the selected provider and all configuration fields already exist.

- Enable `GatewayKind::Openrouter` for Rust, `--provider openrouter` for CLI/ACP, and `options.model.provider = "openrouter"` for deployments. Default model is `z-ai/glm-5.3-flash`. Production transport uses only `https://openrouter.ai/api/v1/chat/completions`; private legacy lookup reads only `OPENROUTER_API_KEY`, environment before the selected dotenv file. Configured references keep exact consumer/destination scoping. Literal loopback fixtures always use a fixed synthetic key and cannot receive a supplied key.
- Use the shared direct HTTP/SSE transport, preserving its client reuse, no redirects/retries/proxy inheritance, deadlines, cancellation and byte/frame bounds. Serialize the same stable instruction/tool prefix and complete ordered message/tool-call history on each turn. Request one selected model, streaming, max output tokens and sequential tool calls. Omit the deprecated `stream_options.include_usage` on OpenRouter; preserve Vercel's existing request mapping. No ordered model fallback or remote accounting lookups are added.
- Assemble fragmented tool names/arguments and call IDs through the common normalized events. Ignore bounded SSE keepalive comments. Tool names map to the same built-in registry; unsupported names, malformed IDs/indexes, incomplete UTF-8/JSON, oversized data and inconsistent finish states fail with closed codes. Provider metadata/reasoning content is not copied into text, tool arguments, telemetry or diagnostics; opaque reasoning continuation is not supported in this slice.
- OpenRouter may send one final non-null usage object with empty choices, or a content-free choice repeating the already-observed finish reason. Accept the repeated reason only on that accounting frame, with an empty/absent content delta and optional assistant role. Reject duplicate usage, mismatched finish, new content/tool calls after finish and duplicate ordinary finish chunks. Yield one normalized finish at `[DONE]`, after all accounting is assembled.
- Map `prompt_tokens`, `completion_tokens`, `prompt_tokens_details.cached_tokens` and `prompt_tokens_details.cache_write_tokens` to nullable native counters. Preserve absent/null fields as unknown; zero is known zero. Parse counters as unsigned integers with checked arithmetic. Do not add reasoning/cache tokens to totals a second time.
- Map only `usage.cost` (the account charge in USD-denominated credits), not `cost_details.upstream_inference_cost`. Parse the raw JSON decimal number without binary floating point and convert to integer micro-USD, rounding a fractional micro-USD upward once per call. The granularity adjustment is less than one micro-USD per call; this normalized reported amount is not an attested hard ceiling. Reject negative, malformed, overlong or overflowing numbers. Missing/null cost remains unknown; explicit zero remains zero. Emit at most one cost event before the one finish. Do not fetch prices or infer costs from tokens. Both gateways continue to reject unsupported hard aggregate ceilings before delivery.
- HTTP rejection does not expose response bodies. Midstream error objects become closed provider-rejected failures; disconnected or malformed streams retain response-received delivery certainty. Cancellation drops the owned request/socket, preserves completed-call accounting and never claims a billing refund. One native terminal outcome drives CLI JSON, ACP and OTel.

P02 must execute actual file-read round trips through CLI and ACP, preserve byte-stable prefixes/call IDs, exercise fragmented UTF-8/SSE/arguments, accounting/repeated finish/absent fields, pre/midstream failures and cancellation, and prove private credential resolution, all-surface redaction, connection reuse and destination trust with synthetic fixtures. Retain a runnable terminal command and matched performance. Actual credentialed CLI/ACP proof remains C3.7.
