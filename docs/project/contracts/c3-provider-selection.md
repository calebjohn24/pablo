# C3.5 provider selection and transport

Frozen for C3.5 before implementation, with the user's explicit model choice applied. The [C3.6 adapter contract](c3-openrouter.md) now enables OpenRouter execution and extends its accounting capabilities; the C3.5 availability statements below are historical.
Deployment schema remains v1 and contract revision becomes `c3.5`.

- Provider selection is `vercel` (default) or `openrouter`, through `--provider`, `options.model.provider` and Rust `GatewayKind`. Vercel defaults to `zai/glm-5.3-flash`; OpenRouter defaults to `z-ai/glm-5.3-flash`. Explicit model IDs override the provider default. Provider tests and live smoke commands use these selected models; deterministic fixtures still make no paid calls.
- Omitted model ID/endpoint follow the selected provider. Explicit inherited values remain explicit; switching providers never silently rewrites operator-authored IDs/endpoints. Fixed production destinations are `https://ai-gateway.vercel.sh/v1/chat/completions` and `https://openrouter.ai/api/v1/chat/completions`. Cross-provider and arbitrary endpoints reject. Existing endpoint/model authority checks still apply.
- OpenRouter configs may load, inspect and render at C3.5. Preparing or executing them fails with `config_unsupported_feature` owned by C3.6 (or a stable legacy provider-unavailable error) before credential reads, telemetry/trace creation or provider delivery. Open Responses remains unavailable until its owning checkpoint. Capability metadata describes the implemented adapter, not an attestation about a remote model or catalog.
- `ModelProfile` exposes provider, selected model, fixed endpoint/protocol, adapter availability and implemented text/tool/usage/cost/accounting capabilities. Vercel's existing text/tool/usage behavior remains; neither adapter attests hard accounting bounds. Unknown model IDs are not looked up during offline resolution.
- Configured credentials remain ordered explicit references, scoped to `provider.vercel`, `provider.openrouter` or `otel.headers` and the exact destination. Only absent sources fall through; invalid present values fail. Host keys, token/dotenv files and environment references never enter model metadata or serialized diagnostics.
- Legacy Vercel precedence remains primary environment `AI_GATEWAY_API_KEY`, alias environment `VERCEL_AI_GATEWAY`, then primary/alias in the selected env file (default invocation `.env`). OpenRouter uses only `OPENROUTER_API_KEY` from environment then that file when its adapter ships; it must never fall back to Vercel keys. No credential parser sources shell or mutates environment. Known gateway credential names cannot be reclassified as non-secret environment options.
- A host-only synthetic fixture destination accepts literal loopback HTTP, without credentials/query/fragment; it always supplies a fixed synthetic token and never accepts a real-key override. Selecting an unavailable provider cannot bypass admission through a fixture URL.
- Extract the existing private HTTP/SSE transport without changing Vercel request or response mapping: one reused reqwest client, no redirects/retries/proxy inheritance, 60-second connect bound plus request deadline, 128 MiB request/response bounds, 32 MiB SSE frame and one million frame bounds, redacted errors and drop cancellation. Provider-specific normalized mapping remains adapter-owned. Ordered model fallback remains C3.10–C3.12.

The public OpenRouter catalog and official Vercel model listing were checked on 2026-09-09. The user-selected OpenRouter model is present and advertises `tools`, `tool_choice`, `max_tokens` and reasoning settings; the retained [candidate metadata](../fixtures/c3-openrouter-candidate.json) is not a live execution proof. C3.6 must test fragmented tool arguments, keepalive comments, final accounting chunks, absent usage, pre/mid-stream errors, once-only cost/usage and cancellation. Current OpenRouter usage documentation says final usage is automatic and `stream_options.include_usage` is deprecated; retain Vercel's wire behavior independently. C3.7 must run both actual CLI and ACP proofs using this selected default, without substituting mock results.
