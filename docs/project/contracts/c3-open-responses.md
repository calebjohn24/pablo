# Open Responses contract — OR01 / C3.9 implementation

Frozen at C3.8 and implemented at C3.9 in the default core and executable. This contract selects HTTP/SSE text, function tools and lossless supported continuation for the native third provider path; it does not claim the entire upstream feature set.

## Immutable authority and executable examples

Pin [openresponses/openresponses at `92c12d96d7b61d6d15e2214daa5e9c6000ab6e1c`](https://github.com/openresponses/openresponses/tree/92c12d96d7b61d6d15e2214daa5e9c6000ab6e1c), specification/OpenAPI release **2026-04-24**. The [pin manifest](../fixtures/c3-open-responses/upstream-pin.json) records exact upstream paths, SHA-256 hashes and byte counts for the unmodified released OpenAPI, specification, acceptance tests, SSE parser and Apache-2.0 license. Resolution and ordinary acceptance use checked-in bytes, never the mutable website or remote schema retrieval.

[OR01 fixtures](../fixtures/c3-open-responses/README.md) contain three requests and SSE responses with two tool rounds, multiple output items/content parts, Unicode text, assistant phases, opaque reasoning, a streamed reasoning summary, exact tool correlation and usage. `node --test docs/project/fixtures/c3-open-responses/audit.mjs` checks request/event shapes against the untouched upstream OpenAPI 3.1 schema and independently checks fixture consistency. Upstream acceptance families `basic-response`, `streaming-response`, `system-prompt`, `tool-calling`, `multi-turn` and assistant phase preservation inform this subset; the whole upstream suite is neither run nor claimed. Image, compaction and WebSocket families are outside it.

Two upstream details are intentional: summary event discriminators are `response.reasoning_summary_text.delta` / `.done`, despite older wording in their descriptions. `ReasoningBody` permits nonempty raw content on output while `ReasoningItemParam.content` permits only null on input. The selected profile therefore preserves opaque reasoning and `summary_text` but rejects nonempty raw reasoning; silently dropping or flattening it is not a valid continuation strategy.

## Configured capabilities and destination authority

C3.9 advances configuration schema-v1's contract revision to `c3.9` and enables `model.provider = "open_responses"`. The C3.9 loader accepts these provider-specific fields; older loaders reject them:

| Field under `options.model` | C3.9 meaning |
| --- | --- |
| `id` | Explicit endpoint-specific model, 1–256 UTF-8 bytes, no whitespace/control. No inferred model/catalog lookup; Vercel/OpenRouter GLM defaults stay unchanged. |
| `endpoint` | Explicit complete POST URL, including its path, at most 4,096 bytes. HTTPS, no userinfo/query/fragment, no redirects. Never append `/responses` implicitly. Arbitrary host selection is operator/host authority, not model authority. |
| `capability_profile` | Required literal `open-responses-text-tools-v1`; missing, unknown or incompatible profiles reject before credentials/effects. This is operator-declared configured capability resolution, not a network handshake or attestation about an untested model. |
| `credential` | Existing named reference; exact consumer `provider.open_responses` and resolved destination must match. Explicit deployment must declare the reference. |
| `auth_header` | Default `Authorization`; ASCII HTTP token, at most 128 bytes. Allow `Authorization` or a custom `X-*` application auth header ending in `-api-key`, `-auth-key`, `-auth-token`, `-access-token` or `-authorization`; case-insensitive validation rejects `X-Forwarded-*`. Transport, routing, proxy, cookie, body, tracing and duplicate headers cannot be overridden. |
| `auth_scheme` | `bearer` (default) prefixes one `Bearer `; `raw` sends only the privately resolved token. No header value or inline secret appears in config. |

The profile declares streaming UTF-8 input/output text, function tools, multiple sequential tool rounds, full-input continuation, opaque reasoning plus summaries, assistant phase retention, token/cache-read usage and automatic endpoint caching. It declares no client cache-control pass-through, pricing, cost report, hard accounting bounds, multimodal input/output, provider-hosted tools, structured-output enforcement, extension items or WebSocket/background/compaction support. Require `max_output_tokens >= 16` at admission to honor the pinned schema; do not silently raise a smaller host allowance. Tool choice maps `allow_tool_calls` to `auto`/`none`; no unsupported request is delivered just because the endpoint accepts JSON.

Offline render/explain/profile metadata expose the adapter's immutable revision, configured profile, protocol, requested model and exact destination. Runtime safe identity records profile/revision and requested versus returned model; an endpoint may report a resolved model alias without changing the credential destination or adapter identity. Capability claims remain scoped to this configuration. Existing model/endpoint/credential authority locks apply to all these fields. Headers cannot be supplied by task content. This profile is available via the same configured CLI, ACP and Rust admission path; legacy provider-only invocation without endpoint/model/profile rejects with a useful configuration error instead of guessing a destination.

Credentials retain ordered environment/token-file/dotenv-file/host reference semantics: absent falls through, invalid present fails, exact consumer and destination exposure, no fallback to other gateway keys. Open Responses explicit deployments have no implicit global key name. Never expose leases in Debug, task/event content, ACP errors, native traces, OTel or shell/MCP/child environments. Mark the actual header value sensitive. Reusing the transport client must not cross a credential/destination scope. The existing host-only literal-loopback HTTP fixture override always uses its synthetic token, never a real credential; production plaintext HTTP is outside this profile.

## Request and continuation mapping

POST one JSON request with `stream:true`, `store:false`, `background:false`, `truncation:"disabled"`, exact model, stable instructions and tool list, `parallel_tool_calls:false`, and the requested output-token bound. Request `include:["reasoning.encrypted_content"]`. Use full ordered `input` history; omit `previous_response_id` rather than depend on server persistence or silently retry a missing response. Do not send pricing, gateway routing, metadata, logprobs or reasoning-effort options implicitly.

Initial user text maps to a `message` with role `user` and `input_text` content. Built-in descriptors map to flat `type:"function"` definitions using the existing reversible wire-name mapping (`fs.read` → `fs_read`), description, full argument schema and `strict:false`; local validation remains authoritative. Tool arguments are accumulated JSON strings and validated as objects using the same tool registry, budgets and policy before execution. `call_id` is the tool/result identity; output item `id` and `output_index` are separate protocol identities and cannot replace it. IDs are nonempty and bounded; duplicate call IDs across the task reject. Tool output maps to `function_call_output` with the original `call_id` and serialized actual result string, never a guessed success or copied arguments.

For each completed response retain all supported ordered output items before appending the actual tool results: assistant messages with content and optional `phase`, function calls with original wire IDs/names/arguments/status, and reasoning items with summary/opaque encrypted bytes. Streamed text is projected once; terminal snapshots reconcile rather than re-emit text or tools. Any wire-to-input projection must validate against both schemas. Empty reasoning `content` may be omitted on re-input because it has no payload; nonempty raw content rejects. Preserve summaries as private continuation even though upstream permits displaying them. Opaque bytes are uninterpreted and never decrypted or merged into normal messages.

The runtime owns continuation per task, not in a provider-global mutable cache. Add a private typed continuation carrier to the provider-neutral boundary, scoped by provider, exact endpoint, requested/resolved model, protocol revision and capability profile. It must not serialize through public native/ACP/task/OTel output or Debug, even with trace content capture. A completed response may commit its continuation only after complete stream validation. A cancelled/failed partial response cannot seed the next task or a different provider. Its bytes count toward the root context allowance, including shared history without double-charging duplicate projections; capacity rejection happens before storing/growing retained state. Dispose at task completion. Later fallback may carry it only across explicitly compatible scopes; opaque state cannot silently migrate or disappear.

## Stream state machine

SSE requires bounded UTF-8/JSON decoding across arbitrary byte boundaries, comments/keepalives, CR/LF/CRLF and multiline data. The `event` field is mandatory for JSON frames and must equal JSON `type`; the final `[DONE]` sentinel is a data-only exception. Preserve event names in the shared decoder for this adapter while keeping existing gateway behavior. Numeric sequences are nonnegative u64 and strictly increasing (gaps allowed); reject duplicate/reordered sequences, duplicate JSON structural fields and inconsistent response/item identities.

| Event/state | Validation and normalized effect |
| --- | --- |
| `response.created` → `response.in_progress` | Exactly one created first; matching response ID, in-progress status, initially empty output. In-progress is optional if creation already declares that state; at most one explicit transition before item events. Queued/background execution is unsupported. |
| `response.output_item.added` | Contiguous new output index, unique item ID, supported type. Message begins assistant/in-progress with empty content; function call begins in-progress with stable nonempty name/call ID and empty arguments; reasoning begins empty summary/content. Track independent item state, allowing valid interleaving. |
| `response.content_part.added` | New contiguous content index on an open assistant message; `output_text` with empty text/annotations. Multiple parts are supported. |
| `response.output_text.delta` → `.done` | Require open matching item/part, concatenate bounded UTF-8 text, stream deltas promptly. Done text must exactly match accumulated text; no later delta to that part. |
| `response.content_part.done` | Require text done; exact part snapshot, then close once. |
| `response.function_call_arguments.delta` → `.done` | Require matching open function item; bounded concatenation, then exact argument-string match; a completed function item must contain a valid JSON object. An incomplete item may retain truncated JSON, but cannot execute. Emit normalized tool identity/argument deltas once; execution waits for successful terminal validation and existing runtime admission. |
| `response.reasoning_summary_part.added`, `response.reasoning_summary_text.delta` / `.done`, `response.reasoning_summary_part.done` | Same indexed open/delta/done/close rules for `summary_text`, but retain privately and emit no public text. Encrypted content is retained from the final reasoning item. |
| `response.output_item.done` | All declared substreams closed; exact identity, phase and accumulated contents. Completed function IDs/names/arguments cannot change. Reasoning final summary matches its substreams. Close once; no later updates. |
| `response.completed` | Exactly one response terminal; status completed, no error/incomplete detail, full ordered output exactly matches closed items, usage validated once. Select `ToolCalls` if completed function calls exist, otherwise `Stop`. |
| `response.incomplete` | Status incomplete and known `max_output_tokens` reason maps to `Length`; the last item may be incomplete, no subsequent item, all returned state must reconcile. Never execute truncated calls. Other reasons reject explicitly; no inferred successful finish. |
| `error` / `response.failed` | Closed provider rejection, response-received certainty, no raw code/message/body in diagnostics. Abort promptly; never dispatch queued tools or retry. A failed terminal's usage cannot turn the task into a success. |
| `[DONE]` | Required after exactly one completed/incomplete terminal; only then emit one `Finished` with assembled usage, followed by adapter EOF. Missing terminal/DONE, a second terminal or content before DONE after a terminal fails. Drop the owned HTTP body after DONE rather than wait indefinitely for remote socket closure. |

Accept only the selected items/events above. Refusals, image/audio/video/file content, provider tool results, compaction, namespaced/unknown item or event variants, nonempty annotations/logprobs, nonempty raw reasoning and unrepresentable semantic fields produce `unsupported_provider_content`. Add this closed failure code to the typed/task schema at C3.9. Unknown optional nonsemantic response metadata and bounded SSE obfuscation padding may be ignored; unknown semantics must never be flattened into text or falsely accepted. Malformed shapes, invalid transitions and duplicate/reordered data produce existing `malformed_stream`. No unsupported raw value is copied into a diagnostic.

## Accounting, capacity and cancellation

Only terminal `usage` settles the call. Null usage maps all native counters to unknown. A present usage object must carry valid unsigned u64 `input_tokens`, `output_tokens`, `total_tokens`, cached input and reasoning output detail; checked totals must agree, cached input cannot exceed input, reasoning cannot exceed output. Map input/output/cache-read directly. Cache-write and cost remain unknown because the pinned schema reports neither. Never add reasoning or cached tokens to totals again, infer pricing, parse provider extensions as money, or attest hard ceilings. Explicit zero remains zero. Existing exact decimal-string task accounting and conservative uncertain-delivery settlement remain authoritative.

Share transport mechanics: one reused direct reqwest client, no redirect, proxy inheritance, hidden retry or detached task; 60-second connection deadline bounded by remaining run duration. Bound before allocation: request 128 MiB, response 128 MiB, SSE frame 32 MiB and one million frames. Adapter retained state also has a 32 MiB compiled ceiling, narrowed by remaining root context; at most 4,096 output items/parts per response in total, 128 function calls per response, IDs ≤256 bytes (call ID and function name ≤64), nesting depth ≤128. JSON decoding additionally rejects containers above 4,096 entries and frames above 65,536 values. Argument/text/result bytes also obey existing root/tool/context limits and the upstream request's 10 MiB string maxima. Count input and continuation wire size before delivery; overflow or exceeded bounds fail with closed diagnostics, never unchecked index allocation or partial tool execution. These are protocol/state limits and do not reintroduce default filesystem-work quotas.

Cancellation or deadline drops the owned stream/client operation and uncommitted continuation. Join any runtime-owned work using existing semantics; keep completed tool effects and completed-call usage, leave unreported delivered-call accounting unknown, and emit one native terminal outcome. Do not claim remote cancellation or billing refunds. Tests must observe socket closure and a subsequent clean task on the reused provider/ACP process.

## C3.9 execution gate

OR02 must run the checked-in conforming stream through actual core, CLI and official TypeScript ACP, replacing fixture tool results with real workspace reads and verifying the next request's exact complete input history. Cover two tool rounds, first-text delivery before terminal, all phases/parts, opaque reasoning and summary retention/redaction even with content capture, usage/null/zero/large integer cases, resolved capability identity, credential/header isolation and transport reuse.

Negative coverage must include schema-valid invalid transitions, duplicate/missing/changed IDs and call/result correlation, omitted/mismatched SSE names, missing/duplicate terminal, missing DONE and repeated DONE without duplicate effects, unknown semantics/modalities, malformed JSON/UTF-8, duplicate fields, oversized frames/items/continuation, response-body disconnection, HTTP rejection/redirect and cancellation before/after tool completion. Assert no duplicate text/usage/tool side effects, no secret/private-state leaks across CLI/ACP/native/OTLP, exact closed errors and conservative accounting. Retain current Vercel/OpenRouter regressions and matched release performance before merging. A paid Open Responses endpoint is unnecessary; ordinary acceptance remains offline.

C3.9 narrows custom authentication names to recognizable auth suffixes so routing and tracing headers cannot be selected. The first valid DONE is logical EOF and drops the body: subsequent bytes, including another DONE, are not interpreted. This follows the lifecycle table above and prevents indefinite waits for remote closure. `tests/open-responses.test.ts` exercises OR02 through the actual executable and Rust measurement host; the upstream audit remains a separate artifact check.
