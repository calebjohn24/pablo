# C2 single-agent contracts

This document freezes behavior selected at C2.0 for implementation in C2.1–C2.5. Current implementation truth remains in the source and [runtime](../../runtime.md), [shell](../../shell.md), [ACP](../../acp.md) and [telemetry](../../telemetry.md) documents. These selections do not change the shipped `c1.2` schema revision. Each implementation checkpoint versions and documents its actual wire additions before advertising them.

## Gap review

The review uses [the brief](../../context.md), sections 12.1/12.5/12.7/12.8, 14.3/14.4, 20.3, 29.1 and 30, together with `crates/pablo-core/src/{contracts,tool,runtime}.rs` and `crates/pablo/src/main.rs`.

| Surface | Observed C1 implementation | C2 selection / remaining boundary |
| --- | --- | --- |
| Runtime and transport | Sequential model/shell loop, typed outcomes, cancellation, independent tasks in a reusable ACP process | Reuse this lifecycle; no new scheduler or session persistence |
| Filesystem | Registry contains only `shell.run`; workspace policy constrains shell cwd | Read/list/search in C2.1 and write/edit in C2.2; static roots with no-follow traversal |
| Task output | CLI streams text; successful outcome includes output and usage; ACP carries native outcome metadata | C2.3 adds a typed task envelope and all-outcome accounting; model JSON Schema validation/repair remains alpha.2 |
| Policy | Tool opt-in; workspace/environment/platform denial enums; sanitized shell environment | Exact tool/executable/root rules and observable IDs; no interactive approval or sandbox claim |
| Accounting | Optional model/tool counts, time/byte/event bounds, per-call requested/reported output-token check; aggregate usage only on completed outcome | All-outcome accounting and opt-in aggregate ceilings with conservative admission; unknown values stay unknown |

## Shared filesystem contract

Qualified identities are `fs.read`, `fs.list`, `fs.search`, `fs.write`, `fs.edit`; provider-valid aliases must map bijectively and preserve native names/call IDs. Empty registries grant none. Hosts can enable reads without writes or shell. Standalone CLI/ACP enable reads alongside their existing shell default; `--no-filesystem` disables all filesystem tools and writes require `--allow-write`. Reject contradictory `--no-filesystem --allow-write` configuration. `--no-shell` disables only shell once filesystem tools ship; update help to explain this changed capability combination. No flag overrides a host deny. MCP and arbitrary external tool registration remain deferred.

All input schemas declare Draft 2020-12, reject unknown fields, NUL and invalid types, and enforce the existing total argument-byte bound before execution. Paths are nonempty UTF-8 strings of at most 4,096 bytes; `.` denotes the workspace for directory operations. Relative paths start at the canonical workspace; absolute paths must be inside it and the operation's allowed roots. Reject `..` components instead of normalizing them. Root matching uses path components, never string prefixes; no glob, tilde or environment expansion. Canonicalize the host-selected workspace once at admission. Configured roots must be existing directories within it; configuration can narrow, never widen that workspace.

After admission, reject symlinks in every traversed path component, including internal symlinks and final targets. Listing may report a symlink entry's name/type but never its target or contents; search skips symlink entries. Use directory-relative no-follow operations anchored to owned directory handles; a canonicalize-then-open check alone is insufficient. Only regular files and directories are supported; reject devices, sockets and FIFOs before opening for data. Hosts still own isolation, hostile mount changes and interference by other processes. Non-UTF-8 directory names produce a bounded `unsupported_encoding` error rather than lossy names that could address a different file.

Reads operate on a bounded in-memory byte snapshot: at most 8 MiB per file by default, configurable by the host, with checked allocation and the run deadline. Check the cap while reading, not only through initial metadata. Use the opened file's bytes for SHA-256 revision and content. Reject NUL or invalid UTF-8 content as `unsupported_encoding`; no lossy conversion. Return workspace-relative paths with `/` separators. Concurrent external changes are not a multi-file snapshot guarantee.

Common optional request fields are `timeout_ms` (positive) and `max_output_bytes` (at least 1,024), narrowing the host tool duration and serialized-result capacity. C2.1 clarified the request minimum to match the existing host minimum: a result must have enough room to represent bounded errors/metadata. The complete serialized `ToolResult`, including escaping and metadata, must fit. Metadata does not bypass caps. Hard work/result exhaustion returns an explicit limit and stops the run; a requested page or match limit is ordinary successful truncation. Never return an apparently complete listing/search after exhausting a hard work bound.

Filesystem work quotas are opt-in following the user's C3.3 correction (D038): file bytes, visited entries, depth and scanned bytes default to unlimited. Rust uses `Option<usize>` (`None`); deployment fields accept `"unlimited"` or a positive integer. Explicit host quotas are checked incrementally and still map exhaustion to `limit_exceeded` / `filesystem_work`. Output bounds, deadlines, cancellation, UTF-8 validation, path containment and revision-checked mutation remain. File snapshots and sorted directory enumeration retain data proportional to the file/directory; operators can explicitly cap that work. Search uses iterative depth-first frames so there is no implicit recursion-depth quota. The former C2 defaults (8 MiB/file, 10,000 entries, depth 32, 64 MiB/search) remain historical in C2 evidence. Serialized-result exhaustion retains `tool_output_bytes`. Successful directory enumeration is sorted by UTF-8 path bytes. On unchanged input, traversal is sorted depth-first; no `.gitignore` or hidden-file filtering is implicit. Denied subtrees are skipped without reading contents or disclosing descendants; an explicitly requested denied path fails policy evaluation.

Each dispatched tool emits tool start/finish and a run-child `execute_tool fs.*` OTel span with matching IDs/timestamps; filesystem calls emit no shell/process-start event. Paths, content, queries/matches, revisions and errors containing OS paths are content: redact them from default native traces and never export them to OTel. Allowlisted rule IDs and closed outcome/error codes are safe metadata. Tool futures check cancellation/deadline between bounded work units and join owned work before returning; a detached blocking worker is not cleanup. Local syscalls can stall outside the runtime's control; no universal cancellation-latency bound is claimed for arbitrary mounted filesystems.

## Read, list and search

In addition to common fields, only these arguments are accepted. Optional fields take the stated defaults; integers are nonnegative unless explicitly positive.

| Tool | Arguments | Successful filesystem payload |
| --- | --- | --- |
| `fs.read` | Required `path`; `offset` byte position default 0; positive `max_bytes` default 65,536 | `path`, `text`, `offset`, `next_offset` (null at EOF), `size_bytes`, `revision`, `truncated` |
| `fs.list` | Required `path`; `offset` entry index default 0; positive `max_entries` default 1,000 | `path`, `entries` of `{path, type}` where type is file/directory/symlink/other; `next_offset` (null at end), `truncated` |
| `fs.search` | Required directory `path` and nonempty single-line literal `query` (at most 4,096 bytes); positive `max_matches` default 100 | `path`, `matches` of `{path, line, text}`, `truncated` |

`fs.read` offsets must lie on a UTF-8 codepoint boundary and be at most file length. Choose the longest prefix fitting `max_bytes` without splitting a codepoint; if a nonempty next codepoint cannot fit, return `invalid_range`. Revision is lowercase SHA-256 of the entire captured file. `offset == size_bytes` succeeds with empty text and null next offset. Pagination is stateless; callers compare revisions across pages and restart after a change. Listings are direct children only; offsets beyond the current entry count are invalid. Cross-call changes can move entries and are not hidden behind a snapshot/cursor promise.

Search is recursive, case-sensitive literal matching with no regex/glob language. Query cannot contain LF, CR or NUL. Lines are 1-based and split on LF; match text excludes LF and one immediately preceding CR. Return each matching line once even if the query occurs twice. Skip binary/invalid-UTF-8 files and symlinks, but an oversized file is a hard work-limit failure. A match line exceeding the result budget is a hard output-limit failure, not a clipped unexplained snippet. Stop after discovering a match beyond `max_matches` and set `truncated=true`; no continuation token is promised. An unreadable in-policy file returns `io_error` rather than an apparently complete search.

Extend `ToolResult` with an optional tagged filesystem payload; shell fields retain their meaning. Recoverable filesystem errors carry closed codes (`not_found`, `not_file`, `not_directory`, `unsupported_encoding`, `invalid_range`, `conflict`, `match_not_unique`, `io_error`) without raw OS messages. They return to the next model call and mark the tool span as error, allowing an explicit model-selected alternative. Invalid schema arguments, policy denial, timeout, cancellation, hard limits and cleanup/event-sink failures remain terminal as in C1. Policy denial continues to stop the run in C2; the broader brief's model recovery after denial remains deferred in the backlog.

## Mutation preconditions and visibility

`fs.write` accepts required `path`, UTF-8 `text` and `expected_revision`. Null revision means create-only; an existing path returns `conflict`. A 64-character lowercase SHA-256 means replace an existing regular file only if its current bounded bytes match. Missing files with a non-null revision return `not_found`. `fs.edit` accepts required `path`, non-null `expected_revision`, nonempty `old_text`, and `new_text`; it performs exactly one literal replacement. Zero or multiple non-overlapping matches return `match_not_unique` and leave the file unchanged. No line-ending normalization or implicit final newline. New content must fit both the argument cap and host file cap, contain no NUL and be valid UTF-8.

Success returns `{path, revision, size_bytes, created, committed:true}`; revision hashes final bytes. Parents must already exist and pass write policy. Revision-checked replacement/edit require both read and write authority on the target, because they inspect existing bytes; create-only requires write authority. Existing content must satisfy the bounded UTF-8 text contract. Reject non-regular targets and symlinks. Preserve ordinary permission bits (`0777`) of an existing file but clear setuid/setgid/sticky bits; create new files with private mode `0600`. Ownership, ACLs, extended attributes and hard-link identity are not promised; atomic replacement changes the directory entry, leaving other hard links untouched. Expose this limitation in tool descriptions/docs before use.

Create a private bounded temporary file in the target directory, write it completely, recheck revision/target type and policy before commit, and install it atomically. Create-only must use a no-replace primitive; replace uses same-filesystem atomic rename. Clean up temporary entries on all precommit failures. No fallback to in-place truncation or cross-filesystem copying. Promise atomic visibility of complete bytes, not crash durability: directory fsync and durable recovery are outside this slice.

Revision checking is optimistic conflict detection, not an atomic filesystem compare-and-swap against independent writers. Serialize runtime mutations; hosts requiring isolation must provide exclusive workspace access. A test-controlled modification before final recheck must conflict. A modification after that check can race the rename and must not be represented as guaranteed protected.

Check cancellation/deadline immediately before commit. Before that point, cancellation returns uncommitted and preserves the target. Once commit succeeds, report `committed:true` in tool finish even if the run then settles cancelled/timed out. Do not claim rollback of an already visible write. Cleanup failure remains explicit and takes precedence over a clean-cancellation claim.

## Static policy

Use one host-owned policy value for embedding, CLI and ACP startup. CLI/ACP load an explicit `--policy PATH` JSON file (maximum 1 MiB, no environment expansion or credential fields); invalid/unknown configuration fails before provider delivery. Session input cannot widen process policy. C2.1/C2.2 implement the filesystem subset; C2.4 completes these fields:

- `tools`: exact qualified tool names; `executables`: exact absolute paths; `read_roots` and `write_roots`: workspace-relative directory subtrees. Each dimension has `default` (`allow` or `deny`) and ordered `allow`/`deny` arrays of `{id, value}`. IDs are unique across the policy, 1–64 ASCII letters/digits/underscore/dot/hyphen and contain no task data. No wildcard matching. Omitted dimensions use the defaults below.
- First matching explicit deny wins; otherwise a nonempty allowlist requires a match; otherwise the configured default decides. Within a list, first match supplies the rule ID. All applicable dimensions must allow. Capability absence wins first, followed by tool, executable (shell only), then root checks. Mandatory workspace/no-follow/environment constraints cannot be overridden.
- Defaults allow registered tools, permit the existing `/bin/sh` launcher, allow reads within workspace and deny writes. Explicit write opt-in supplies the workspace write default only when the host omitted that dimension; it cannot override a supplied policy default or rule. Built-in decisions use stable `builtin.*` IDs; configured rules retain host IDs. Record the decisive rule for denials and one deciding rule per dimension for allowed calls.
- Shell executable policy concerns Pablo's actual `/bin/sh` launch. C2 does not parse `sh -c` text into an executable allowlist or inspect descendants. Denying `/bin/sh` denies shell; allowing it grants arbitrary commands within host containment. Preserve `PATH=/usr/bin:/bin`, `LANG=C` and `PABLO_TASK_` additions; no new environment forwarding or shell-command pattern language.

The logical built-in denial IDs are `builtin.tool_unavailable`, `builtin.workspace`, `builtin.symlink`, `builtin.environment`, `builtin.unsupported_platform`, and `builtin.<dimension>.allowlist_miss` / `builtin.<dimension>.default_deny`; allow defaults use `builtin.<dimension>.default_allow`. For C1 wire compatibility, mandatory built-in denials retain their native `PolicyRule` enum strings (`tool_unavailable`, `workspace`, `symlink`, `environment`, `unsupported_platform`); their logical identity maps to the corresponding `builtin.*` name. Configured/default dimension decisions carry their full IDs. This explicit C2.5 compatibility clarification preserves generic and legacy ACP fixtures. Dimension names are exactly the four configuration fields above. Evaluate mandatory constraints before configured rules; root checks evaluate read before write when both apply. A read-root denial omits that entry from list/search results; skipped entries still consume traversal work. Rule IDs describe decisions without echoing the requested path or command.

Filesystem policy applies only to explicit filesystem tools; shell cwd uses the workspace boundary as before. It cannot enforce shell file reads/writes. MCP-server, network and child-authority rules remain deferred with their capabilities. No approval UI is introduced.

## Task envelope and terminal truth

`pablo "TASK"` has exactly the `pablo run "TASK"` lifecycle and defaults. Existing command names retain precedence; a task equal to a command name must use explicit `run`. Accept exactly one task positional argument, with flags as for `run`. `pablo run --json "TASK"` writes exactly one compact JSON object followed by LF on stdout after settlement. Text deltas and progress never share stdout; optional human diagnostics go to stderr. Native JSONL remains a separate explicitly selected file. A closed stdout can prevent complete delivery; return failure, never fabricate a second outcome. Serialization has a checked bound derived from configured final-output bytes plus bounded metadata, including worst-case JSON escaping; streaming events are never buffered to construct this object.

Envelope fields are `schema_version` (task-envelope revision `c2.3`), `run_id`, `session_id`, `trace_id`, `outcome`, `accounting`, `error`. Admitted runs have non-null IDs, the native typed outcome, and null `error`. Before admission, IDs/outcome/accounting are null and `error` is `{code}` from `invalid_arguments`, `invalid_configuration`, `credential_unavailable`, `trace_setup_failed`. No raw task/config/path/credential text. With `--json` recognized, parser/configuration errors use this envelope too. Help/version are separate commands, not task results.

`accounting` is present for every admitted outcome: `model_calls`, `tool_calls`, `usage` with existing nullable token/cache field names, `cost_microusd` (nullable), and `charged_tokens`/`charged_cost_microusd` (nullable when no ceiling is configured). All integer values inside this new wire accounting object use canonical unsigned decimal strings (`"0"` or digits without leading zeroes); unknown remains null. Core arithmetic stays integer-based. This preserves u64 values through the existing JavaScript ACP SDK without silently rounding them; the existing native outcome representation is unchanged. At C2.3 cost/charged fields are null; C2.4 populates them when supported. Count model calls at provider dispatch attempt and tool calls at tool dispatch (including dispatched validation/policy failures); pre-dispatch rejection consumes no count. No model calls means known zero usage; a dispatched call missing usage makes that aggregate field unknown. Preserve finished-call usage on later failure/cancellation, including unknown contributors.

Exit 0 means completed, 130 cancelled, 2 pre-admission rejection and 1 any other terminal or delivery failure. Output remains the native final string, even if it contains JSON. No user-schema validation or repair is added. Core, CLI and negotiated ACP metadata share one result builder; ACP's standard stop reason remains a transport projection, including the existing late-cancellation rule. Negotiate envelope metadata and bound framing before advertising it; generic ACP peers retain standard updates/reasons without requiring the extension.

## Accounting admission and settlement

Keep model/tool call caps absent/null as unlimited and zero as disabled. Sequential tools already bound runtime-owned shell groups to one; retain that fixed ceiling rather than add a redundant process knob. This counts owned groups, never every descendant a shell can fork. Retain duration, byte, per-call output-token, trace and event limits. Model calls define the step count for C2; no redundant step counter is added. Descendant process-count containment remains host-owned.

C2.4 adds optional `max_total_tokens` and `max_cost_microusd` nonnegative integer ceilings, default null. Do not fetch prices, infer tokens from text, assume omitted usage is zero or use floating-point currency. A hard ceiling requires a trusted host/provider accounting profile supplying enforced per-call upper bounds for the relevant quantity (`max_call_tokens`, `max_call_cost_microusd`). Bounds are host configuration, never model arguments. Reject configuration before delivery if the selected adapter/profile cannot enforce or attest to the bound; ordinary Vercel usage reporting alone does not qualify. The offline provider can attest to a bounded script. A live ceiling profile requires documented enforcement evidence, not merely a configured number.

Before dispatch reserve the full per-call bound; if it exceeds remaining budget, return `limit_exceeded` with `total_tokens` or `cost` without sending. Zero ceilings permit no positive reservation. Use checked integer arithmetic. Settle with known actual usage/charge, releasing unused reservation; if actual is unknown or delivery may have happened, retain the full reserved charge while actual usage/cost remains null. A definitely-not-sent failure releases reservation but retains its dispatch-attempt count and has known zero actual usage/charge. Conservative charged values must not be labeled provider billing. Charges and remaining capacity stay visible in task/native accounting on every outcome; remaining capacity is derived from configured ceilings minus charged values.

Token charge is input plus output (cache fields are subsets, never added again). Cost is only an explicit normalized provider-reported amount under a supported profile; absence stays null. Sum each actual field with checked arithmetic; missing/overflow stays unknown and does not release reservation. Actual above an attested bound is `accounting_bound_violated`, a terminal failure retaining representable actuals with no further dispatch. This reports a violated assumption, not a retroactive spending guarantee. No retries, fallback, rerouting, hidden final model call or guessed-price conversion follows exhaustion.

Expose the optional ceilings as `--max-total-tokens` and `--max-cost-microusd` for CLI/ACP startup, with equivalent core fields. The selected provider adapter owns its attested profile; a caller cannot certify a live bound by supplying a flag or policy number. When both reservations fail, report the token limit first. Validate all values as unsigned 64-bit integers; CLI flags parse decimal input directly and wire consumers can use BigInt on the accounting strings. C2.3's nullable fields reserve the accounting shape; C2.4 documents/version-negotiates these additions before exposing them.

Counters, reservations and actuals reset for each independent task in the reusable ACP process. Deadlines/cancellation and cleanup still apply with accounting enabled. The [fixtures](../fixtures/c2-single-agent.md) define exact arithmetic and failure observations.
