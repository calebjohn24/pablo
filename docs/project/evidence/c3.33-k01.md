# C3.33 — Compatibility/protocol verification

## Implemented contract

[The supported-operation matrix](../../protocol-compatibility.json) lists configuration, ACP, MCP, A2A, Open Responses, Skills and JSON Schema versions, implemented subsets, exclusions and executable gates. [The immutable pin manifest](../../protocol-pins.json) covers 102 schema/fixture/conformance files, seven Rust SDK release identities, two npm SDK integrities and two independently installed Python peer source identities. Upstream references are frozen by commit or distribution identity, with reference bytes and licenses in the compatibility corpus. The offline verifier has no update mode; five mutation controls demonstrate acceptance of current identities and rejection of file, Rust, Node and Python source drift.

Native events and task results now explicitly use `c3.33`. ACP wire protocol remains 1, with current `pablo/v2` / `pablo/task-v2` capabilities. Each project extension has a project-controlled URI, schema, dependencies, bounds, privacy class and generic fallback in [the registry](../../acp-extensions.json). Custom notification methods have explicit v1 names. Actual streamed route, compaction and Skill notifications are schema-checked; captured content is byte-bounded and redacted messages cannot carry summary/instruction content.

Frozen C2 client/schema bytes from `ba8b0ff62b3ccc40c8a6ae704b4450ead12040b3` execute against the actual binary. Legacy unconfigured success/refusal receives c2.4 correlation and c2.3 tasks; configured C3 requests get migration errors before provider delivery. Mixed old-base/new-feature negotiation rejects before initialization is consumed and supports a v2 retry. Generic peers receive standard ACP. A focused Rust test proves new failure variants become safe migration errors rather than invalid C2 metadata, while v2 retains their typed outcome. Task schema controls reject missing validation and intermediate repair states in terminal results.

## Parser and transport coverage

The new deterministic mutation generator produces 258 candidates per seed for configuration, Skill metadata, JSON Schema, A2A cards/replies, MCP frames and Open Responses SSE. Positive controls require valid seeds to succeed; invalid encodings are handled before typed parsing. Existing substantive fixtures cover unknown fields/variants, malformed JSON/SSE/YAML, schema/resource/work bounds, cancellation and teardown. Relevant cases include `output.rs` local-ref/cache/unsupported-contract/diagnostic/cancellation tests, `skills/tests.rs` YAML/Unicode/discovery bounds, Open Responses unknown event/item rejection, MCP malformed catalog/frame/progress/error cases and A2A assignment/stream-loss/cancellation boundaries.

ACP byte mutations first prove valid initialization, then require bounded responses and process settlement. Existing ACP cases exercise malformed/oversized/batched/flooded frames, generic future fields, maximum escaped output, physical-write backpressure, cancellation and peer loss. An idle configured process has no network descriptors/listener, MCP child or trace before a prompt, proved with lsof/pgrep and filesystem/receiver assertions. There is no eager optional-adapter work.
