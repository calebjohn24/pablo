## Matched performance

[Measurement summaries](c3.5-measurements.json) retain methods, hashes, sample counts and distributions. Each variant used 30 samples after five warmups on native macOS arm64 with the existing Node 24.11.0 and Rust 1.98.1 installations. Runs were sequential without concurrent builds/tests. The frozen C3.4 executable hash matches the prior checked-in report. Both versions use the same updated harness with an explicit Vercel GLM model and local HTTP/SSE responses.

Release size changed from 11,197,856 to 11,214,592 bytes (+16,736; about 0.15%).

Final review corrected a stale C3.4 title in the resolved JSON schema. Re-running the release build produced the identical measured executable SHA-256. The measurement summary records the final source fingerprint separately and preserves the original measurement fingerprints.

The first configured pair showed higher CLI/ACP p95 latency (21.656 → 26.249 ms and 15.340 → 20.744 ms). This prompted a reverse-order repeat, retained in full alongside the first pair. Both builds then had much higher ACP medians, with C3.5 slightly lower in that repeat; CLI p95 remained higher (26.470 → 30.629 ms), and core timings also varied substantially. The results show host/workload variability and a remaining observed CLI tail difference, not a demonstrated universal speedup or a stable latency bound. No performance acceptance ceiling exists for this checkpoint; no result was discarded or relabeled as a passing threshold.
