# C3.22 partial — Shared native event budget

The root ledger now counts used and reserved native events across registered
agents, checking both root and per-agent ceilings under the same mutex. Creating
the ledger protects one root terminal slot immediately, including when a host
starts a child before driving the root. Each executed agent claims its run terminal
before its run span starts. Model, tool and compaction operations reserve their
start/finish pair before creating the operation span or reaching provider/tool
admission. Other native events require atomic ordinary admission.

Reserved closing events can settle after admission closes. Consumed delivery
attempts remain spent when a sink fails; dropping a reservation releases only its
unused slots. Nested compaction/model reservations follow the existing lifecycle
stack. Per-agent native sequence numbers and original OTel identities remain
unchanged. The counter is not a root delivery/multiplex sequence. Unscoped runs
keep their existing local event checks and do not allocate shared reservations.

Tests cover a simultaneous reservation race with one winner and no partial
capacity, unused reservation release, duplicate terminal claim/consumption
rejection, root terminal protection against child exhaustion, and a local child
ceiling that leaves root admission available. Two actual runtime executions share
an eight-event ceiling: both model calls start, neither text chunk fits, and all
four promised model/run finishes are emitted within the cap. A separate case has
room for a root run but not a model start/finish pair; it emits no model span and
spends no provider call. A closed ledger after root deadline still emits the
reserved native TimedOut terminal and returns the same outcome. Existing scoped
compaction and supervisor tests exercise nested reservations and joined shutdown.
