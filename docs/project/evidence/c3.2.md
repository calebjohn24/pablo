# C3.2 — Bounded configuration loading and composition

C3.2 implements offline TOML deployment resolution in `pablo_core::deployment`. G02's 21 cases pass through 34 integration tests and six focused boundary/read tests. The public request takes explicit files or an in-memory document, approved roots/bindings, selected profiles, a declared non-secret environment snapshot, typed overrides and host authority. The immutable result exposes validated options, secret references, both fingerprints and source/provenance inspection. No runtime or capability is activated.

## Verified behavior

Imports traverse depth-first in declared order, with importer bodies and then selected profile ancestry applied at deterministic ordinals. User/workspace layers are explicit and lower priority. Scalar/path assignments, recursive maps, replace/append/prepend lists, empty-list clearing and optional unset objects retain source contributions. Equal named records coalesce; unequal definitions conflict. Equal profile declarations apply list operations once while retaining both sources. Cycles, repeated files including hard links/diamonds, duplicate ancestors/IDs, invalid scalar types, unknown fields and inactive unsupported features reject with bounded metadata-only diagnostics.

The production result matches its complete checked-in envelope, including all 91 provenance pointers and source digests. The effective fingerprint remains `sha256:05da699dbe1fad56d03edcd5ed1d0fbceea7932fda05907492187eff08c86c7e`; the input fingerprint remains `sha256:f666c9503d6f2cada8ae91bc2c1c50b9c7415050913bce23ad60130ca35c7e84`. Repeat resolution is identical; comments/CRLF change only input identity, and changed effective values change effective identity. All three independent canonical encoding vectors pass. D035 documents precise provenance operation labels and typed/bootstrap source payloads, refining the earlier hand-authored provenance without changing the frozen config or fingerprints.

Entry/import reads walk opened directory descriptors with no-follow semantics, reject symlinks and non-regular files, and use bounded reads with before/after file metadata. A deterministic paused-read seam catches an actual content mutation between metadata admission and reading as `config_input_changed`; FIFO fixtures reject without blocking. Declaring-file relative paths normalize to portable config references. Workspace/credential/trace paths are validated as references without scanning workspaces, opening secret files or creating trace output.

Locked mode is selected before user/workspace files are opened. An isolated subprocess changes cwd, HOME/XDG, OTel/provider variables and supplies an unreadable synthetic ambient `.env`; both fingerprints remain identical. Explicit forbidden equal assignments reject, permitted limits narrow, and authority survives profile/environment/host option precedence. Workspace-relative ceilings are anchored to the workspace at their declaration so later workspace changes cannot move them. Each policy authority remains a separate layer for C3.3's runtime evaluation.

Missing and present synthetic secret files produce identical snapshots, and synthetic environment secret values never enter inspection or Debug output. There is no credential callback in this API. Configuration resolves no secret bytes, executes no scripts, contacts no provider and initializes no telemetry exporter. Root `.env` and real provider credentials were neither loaded nor printed.

## Bounds

G02-13 maps each bound to executable tests in [the case manifest](../fixtures/c3-deployment/cases.json). Full resolution exercises 1 MiB files, 8 MiB aggregate bytes, 16 file/profile levels, 64 files/profiles/expanded profiles/credentials/path bindings/authority layers, 32 imports per file, eight credential sources, 64 resource attributes, 128 rules per dimension and 1,024 aggregate rules at the limit and one excess.

Structural seams cover 32 parsed levels, 65,536 aggregate value nodes, 1,024 array/map entries, 65,536 origin contributions and 8 MiB config/inspection encoding. The 128-edge guard is tested independently because valid graphs reach 64 distinct files first; the 64-environment-name shape bound is tested independently because the current allowlist has only 35 distinct scalar targets and repeated targets conflict. These are real guard tests, not waived bounds. TOML syntax parsing is protected first by file byte admission and its pinned internal recursion limit; the 32-level/node budget applies during conversion before the typed value tree grows. Inspection size is checked by bounded streaming serialization without first allocating a second full JSON tree.
