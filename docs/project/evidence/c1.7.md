# C1.7 — Runtime performance follow-up

Completed 2026-09-05 UTC. This user-requested follow-up reduces Pablo's trace and ACP costs and reuses process setup across independent tasks. Model/provider routing, prompt changes, caching, call budgets and tool execution order were excluded. C1.6 acceptance and its live evidence remain unchanged.

## Implemented behavior

- Native JSONL serializes borrowed event fields into one reusable, capacity-limited buffer. It preserves content/redaction fields, ordering, terminal reservation and flush behavior; a rejected record never writes a partial JSON line. No temporary JSON tree or cloned task content is needed for redaction.
- ACP checks event capacity with a conservative bound for ordinary text and an exact counting writer otherwise. Physical frames still have a 32 MiB limit. The first text delta of each model operation is delivered immediately; subsequent text retains the 4 KiB/16 ms batching boundary and native sequence ranges.
- Sequential independent sessions share one lazy worker/executor, HTTP client, compiled tool registry and telemetry SDK. Each task owns its input, workspace, parent context, cancellation token, event stream and result. One prompt per session remains enforced; a completed session can be replaced with `session/new`.
- Physical output acknowledgements remain cumulative across tasks. Disconnect/cancellation still wake blocked output and join owned work. The SDK flushes on process shutdown; it is not rebuilt or force-flushed for every prompt.
- ACP trace paths may include `{session_id}` for separate private files. Fixed paths retain exclusive creation and cannot overwrite an earlier task's trace.
- Release builds use thin LTO, one codegen unit and symbol stripping, preserving unwinding and portable target defaults. See D019/D020 in [the brain](../brain.md), [ACP behavior](../../acp.md) and [telemetry ownership](../../telemetry.md).

Added trace time fell approximately 72% on macOS and 79% on Linux. Each traced fixture still writes exactly 390,646 bytes. JSON fields and semantics are preserved; object key ordering can change. Warm ACP prompt p95 was 12.439 ms on macOS and 6.055 ms on Linux. The benefits require a host to retain the ACP process and create a new session for each task; the reference one-task CLI still starts a fresh process.

The first-delta fixture holds the provider response open for 40 ms after writing text, so the result measures delivery without terminal flushing masking the batching delay. It is not model time-to-first-token. Fresh-process prompt and startup measurements do not demonstrate a general cold-start speedup: macOS startup p50 rose by about 0.79 ms, and Linux stayed close to baseline.

## Release profile choice

The macOS experiments retained the old profile as a preliminary comparison and then compared thin versus full LTO on the same implementation. Every candidate used the same harness and has its own source/build fingerprint in the aggregate file. Final measurements above use the final source, including CLI help cleanup.

| Candidate | Default executable | 1,000-event JSONL run p50 |
| --- | --- | --- |
| Optimized code, thin LTO / 16 units / debug-info stripping | 14.55 MiB | 0.944 ms |
| Thin LTO / 1 unit / symbol stripping | 9.74 MiB | 0.872 ms |
| Full LTO / 1 unit / symbol stripping | 8.85 MiB | 1.012 ms |

A separate ten-pair comparison alternated fresh processes; each process ran 30 trace/no-trace pairs after five warm-ups. Medians of the per-process p50s were 0.832 ms traced / 0.372 ms added for thin LTO, versus 0.951 ms traced / 0.488 ms added for full LTO. Full LTO reduced size further but made this traced workload about 14% slower. Thin LTO already fits the provisional 10 MiB headless target on both measured systems, so it is the selected speed/size tradeoff. No compile-time performance claim is made.

## Limits and handoff

These are warm-filesystem microbenchmarks, not remote model/TLS measurements or a native Linux x86_64 release gate. JSONL still adds 82.7% to the untraced CPU-only fixture on macOS and 64.6% on Linux; the brief's provisional 2% writer budget is not claimed as passed. Initial idle RSS is not peak memory or a long-duration leak test. Thirty process samples do not establish stable p99 behavior, and no speculative CI ceiling is added.

The record helper initially rejected the completion entry because its `problems` array included these scoped limitations. Corrective append-only entries preserve that failure and select completion evidence with no unresolved C1.7 problems; the limitations remain documented here and in the handoff.
