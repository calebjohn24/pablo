# C3.29 — Retained Node regression failures

The first full Node run used the default file concurrency alongside Rust checks.
It passed 304 of 305 tests, with one cancelled test: the large-prompt ACP case
reached its 20-second test deadline. That case passed alone in 1.115 seconds.

A subsequent default-concurrency Node run, without Rust compilation, passed 299,
failed one and cancelled five. It took 471.352 seconds. Failures included R03
stream-loss and pre-assignment cancellation deadlines, ACP backpressure and
maximum-escaped-output deadlines, and a fallback-notification count assertion
(one observed versus two expected). Several elapsed times greatly exceeded their
configured test deadlines; the record does not infer a proven cause from that
observation. The fallback case passed alone in 1.335 seconds.

After verifying prior processes had ended, the final current-debug run used
`node --test --test-concurrency=1 tests/*.test.ts`. All 305 tests passed, none
skipped/cancelled, in 117.858 seconds. Test assertions and deadline values were
not relaxed. Five focused TUI Rust tests, Clippy and formatting also passed after
the final presentation fallback for unavailable terminal events. Serial Node
verification includes that final binary and the updated PTY harness.

This supports the final functional acceptance under serial file execution; it is
not evidence that default-concurrency stress is reliable on this host. Keep both
failed runs disclosed and revisit concurrent acceptance if the failure reproduces
under controlled native-platform/compatibility checks. Raw task bodies and terminal
transcripts remain in ignored local logs, not project records.
