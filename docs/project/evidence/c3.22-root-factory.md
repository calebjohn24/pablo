# C3.22 follow-up — Root MCP admission and owned cleanup

The internal RootFactory creates root identity/accounting before capability setup
and reserves conservative MCP session/process capacity before opening tools. A
capacity rejection therefore precedes credential resolution and initialize/list.
A supervisor with selected MCP capabilities rejects construction without a matching
root permit. Successful setup transfers shared permit ownership to the supervisor;
constructor failure retains the factory's copy through tool cleanup.

The manager's persistent shutdown task now joins children, closes root tools, and
then releases root MCP capacity. Dropping a close caller does not drop that task.
Repeated close observes the same result, including cleanup failure. Late cancelled
or expired setup closes its tools before releasing admission. Callers must keep
polling setup after cancellation; abandoning the setup future is not supported.

Regressions prove exhausted capacity starts no process, successful initialization
holds one process/session permit, an abandoned close caller leaves capacity owned,
and repeated close observes a reaped process and zero retained capacity. A hung
initialize fixture confirms cancellation is awaited through process cleanup before
capacity release. The two process-backed tests use the isolated Python fixture
and are explicitly run despite their normal ignored annotation.
