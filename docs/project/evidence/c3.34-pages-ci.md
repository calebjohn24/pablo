# C3.34 — Cloudflare Pages CI handoff

The merged release-documentation change added the Cloudflare Pages workflow and configured its two required GitHub Actions secret names. This follow-up verified that `main` can build and deploy the site through GitHub rather than relying on a local Wrangler login.

## Account alignment

The first `main` workflow run built and tested the site successfully, then reported that `runpablo` was absent from the supplied Cloudflare account. Investigation showed that the project had initially been created under the locally authenticated Wrangler account, while the user-supplied API token belonged to the separate account configured in GitHub.

The initial project was deleted from the local account and immediately recreated with the same `runpablo.pages.dev` subdomain under the supplied account. The credential was provided to the Cloudflare API through hidden stdin and was never written to the repository or project records.

## Verification

- GitHub Actions run <https://github.com/calebjohn24/pablo/actions/runs/34875832090> reran the failed job and passed checkout, Node 24 setup, dependency installation, the five site tests and Cloudflare Pages deployment.
- Browser-use reopened <https://runpablo.pages.dev> after the account move and found the expected title, hero, favicon URL, 1200-by-630 Open Graph metadata and zero horizontal overflow at the active desktop viewport.
- The production Open Graph PNG downloaded after the CI deployment matched `website/public/og.png` byte for byte.
- `node scripts/project.mjs check` and `git diff --check` passed after this handoff was recorded.

Local `npm run deploy` requires credentials for the selected Cloudflare account. The GitHub workflow is the verified production path and holds those credentials as repository secrets.

## Handoff

The release documentation is merged to `main` and automatically deploys to <https://runpablo.pages.dev>. C3.34 remains blocked by the standing packaging hold; C3.34b remains the next ready implementation checkpoint.
