# C3.28 — R03 remote boundaries and tracing

R03 passes through the configured CLI/ACP path. The existing C3.27 runtime needed
no behavior change: independent adverse SDK fixtures and a real Python
OpenTelemetry peer now prove its failure, cancellation and observability contract.
The release executable is byte-for-byte identical to the verified C3.27 binary.

## Lifecycle proof

`tests/a2a-boundaries.test.ts` runs eighteen model-delegation cases (nine through
CLI, nine through ACP), plus four actual root-cancellation cases:

| Case | Verified local outcome and separate receipt |
| --- | --- |
| Cancel after submission, before task assignment | Cancelled; unassigned; no CancelTask without a known ID |
| Cancel after assignment | Cancelled; received canceled state |
| Rejected cancellation | Cancelled; numeric peer rejection retained |
| Completion racing with cancellation | Cancelled; received completed state; no false local success/rollback |
| Lost stream | Remote-task failure; one best-effort cancellation |
| Task deadline | Timed out; separate canceled receipt |
| Oversized artifact envelope | Output-byte limit; rejected content not retained; observed task ID supports cleanup |
| Input-required status | Remote-task failure with distinct input-required typed result and cleanup receipt |
| Nonresponsive cancel endpoint | Cancelled; unconfirmed after the two-second exchange bound |
| CLI SIGINT / ACP session cancel before and after assignment | Root and proxy cancel, proxy terminal precedes root terminal, process cleanup joins |

Every case asserts one card retrieval and one task submission where applicable;
assigned tasks receive at most one CancelTask, with no replay or automatic
resubmission. Metadata-only native records exclude the private root input and
selected remote Part. Model-stop cases preserve exact native terminal outcomes,
root sequence ordering and zero local model/tool accounting on the remote child.
All Pablo runs return within the seven-second test bound, including the
nonresponsive cancellation case. The fixture peer itself may ignore connection
closure and is explicitly terminated/reaped separately; this deliberately does
not assert that Pablo stopped the remote service.

The existing R02 explicit supervisor gate is rerun, including queued cancellation
before any card/task HTTP, shared queue limits, output ceilings and root resource
release. No hard remote-spending guarantee, refund, local file interpretation or
local tool-policy enforcement at the peer is claimed.

## Collector proof

`telemetry_server.py` uses the actual Python OpenTelemetry SDK 1.44.0 and its pinned
OTLP/HTTP exporter. Dependencies are isolated in the fixture environment. The
peer validates matching W3C request headers and metadata, creates its own task span
with original remote IDs, and exports through the real pinned Collector 0.160.0.

[Release Collector receipt](c3.28-collector.json): sixteen spans across negotiated
and generic ACP runs. With the optional extension, the peer span shares the native
trace and has the local proxy span as parent. A generic card still completes with
host trace opt-in but no transmitted extension/context and a separate peer trace.
Local native trace/span/parent/agent identities and exact start/end timestamps
match Collector spans. Remote IDs remain separate. Exported spans, native records
and diagnostics exclude private task content. Stopping the Collector leaves root
and remote outcomes, accounting and typed remote result unchanged, with native
content redaction still verified. This proves local/fixture interoperability,
not compliance by arbitrary remote services.
