## Implemented capability assessment

C2.1–C2.4 implement bounded read/list/search, explicit revision-checked write/edit, shared task JSON/ACP envelopes, static host policy and run-local accounting through one sequential lifecycle. File workers are joined; no-follow directory handles and optimistic atomic mutation semantics remain. The C2 fixture catalog is exercised through Rust and offline CLI/ACP fixtures on both tested platforms. Linux additionally exercises invalid UTF-8 filenames which APFS refuses to create. Both permission tests run as an unprivileged user and actually deny access.

Final review added observable configured **and default** tool/launcher/root policy IDs, including recoverable filesystem results, and OTel denial identity. IDs enter result sizing before mutation effects. A tool whose start event cannot be delivered is no longer counted as invoked. A dedicated sink-failure test proves zero tool calls and retained prior model accounting. D027 explicitly maps logical mandatory `builtin.*` identities to the existing C1 enum wire values to retain compatibility; native revision remains c2.4. Development checks caught an initially misplaced assertion and a backpressure fixture waiting on buffered redacted trace data. The latter now explicitly captures synthetic content so the large result flushes the trace at a real observable barrier. Both were corrected before final passing runs. No unresolved runtime test failure remains.

The alpha.1 single-agent capability slice is implemented and locally usable, but this is **not alpha.1 release acceptance or the full 0.1 product**. Remaining release gates include the native target, release-stable extension naming/ownership, doctor/distribution/packaging and the separately deferred extensibility/interoperability work. No tag, publish, provider routing, prompt performance optimization, automatic retry/fallback, child agent, durable state or performance CI ceiling was introduced. Hard aggregate ceilings remain explicitly unsupported for the live gateway until an adapter can attest enforceable bounds; reported usage is not a spending guarantee.

## Matched release measurements

[Sanitized aggregate reports](c2.5-measurements.json) retain platform/build/source/harness hashes and percentiles. The baseline is the saved C1.7 binary from `8b8cc69`, with source fingerprint `eecfd91a4141bc8ced4522c2d4b8d08b002cb429dc79369af1a15d2b1216f060`, rerun on the current harness. Both builds use the same fixed loopback workload and C1.7 methodology: 30 samples after five warm-ups, rotating paths, warm filesystem, no forced cache eviction. The VM was stopped and no builds/tests ran concurrently with timings. Raw arrays remain ignored.

An initial single-process event sample showed approximately 6% higher traced time. Ten alternating process pairs, each containing 30 trace/no-trace samples after five warm-up pairs, narrowed that observation to 1.8% on median traced time; event delivery itself was unchanged. Each final traced run writes 390,882 bytes versus 390,646, adding terminal accounting. The paired results avoid attributing a single scheduler/cache sample entirely to code.

The measurements show preserved warm responsiveness and immediate first text, with modest fresh-setup, memory and size costs. Extra reusable filesystem schemas/catalog and accounting metadata are plausible contributors to the fresh-prompt difference; that attribution is an inference, not an isolated schema-compilation measurement. Timers separate process startup, core run (provider/tool/SDK setup excluded), fresh/warm ACP prompt and transport delivery; they do not measure remote model latency. The existing release profile was retained. The binary remains just below the provisional 10 MiB headless target; no provisional threshold was promoted into a pass/fail ceiling and no universal performance-equivalence claim is made.

## New filesystem workloads

`scripts/measure-filesystem.ts` runs 30 samples after five warm-ups for each workload, with two loopback calls, actual result assertions and negotiated task accounting in fresh sessions of a reused process. Tool time uses native start/finish timestamps and includes the joined worker and filesystem work. Prompt time also includes gateway parsing and ACP delivery. Fixture creation and reusable process/catalog/SDK setup are excluded. These capabilities have no C1 native-filesystem equivalent; they establish a new baseline.

| Sorted list of 1,000 entries | 0.954 / 1.180 ms | 1.777 / 2.203 ms |
| Literal search of 1,048,700 bytes in 100 files | 2.087 / 2.352 ms | 2.606 / 2.833 ms |

Mutation fixtures repeatedly install verified equivalent bytes with current revisions, so each sample exercises the same precondition and commit work. They do not claim fsync durability or arbitrary-storage performance.
