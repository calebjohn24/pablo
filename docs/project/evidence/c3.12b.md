# C3.12b — Stronger task-relevant compaction

The user requested substantially more reduction and explicitly selected keeping
**task-relevant details in the summary**, rather than an exact raw-output archive.
This refines C3.12a without adding a recall tool, another summary pass or new budgets.

## Change and behavioral proof

`keep_recent_turns` now defaults to zero (accepted range 0–32). Summarize every
completed turn, including the newest bulky tool result, when the summary source
fits. If capacity requires a raw suffix, search up to 32 retained groups and choose
the smallest admissible suffix, honoring an explicitly configured minimum. If no
source fits, retain original history and fail explicitly. Unknown provider capacity
still cannot be inferred; a rejected summary does not create another attempt.

The handoff prompt asks for constraints, decisions/reasons, exact values/units/dates/
identifiers, artifact paths/revisions, committed effects, uncertainty, failed
approaches and next actions. Dense factual sections replace raw logs and repetition;
there is no hard compression ratio that could force useful facts out. Original task,
instructions/tools and effect/ID accounting remain unchanged. Private carriers are
included in the selected source and discarded only at the successful boundary.

Core tests cover full replacement, explicit retention and capacity-required retention.
Twelve success cases cover all three adapters × threshold/overflow × full/explicit
retention through CLI and fresh ACP sessions. Facts occur in older and newest file
results; tests assert they enter the summary source and survive in the handoff and
continuation. Actual file-write effects are not replayed. Existing invalid-summary,
privacy, session-isolation, budget, cancellation and recovery tests remain passing.

## Live fidelity proof

A small user-authorized OpenRouter check used `z-ai/glm-5.3-flash`, one real file
read, one summary and one continuation. Only Pablo read the file-only `.env`
credential reference; the harness did not read, source or print credentials. See
[the sanitized result](c3.12b-live.json). Seven exact facts survived in both summary
and final answer, including an amount, currency, date, account identifier, artifact
path, revision and pending action. Context fell from 22,623 to 4,616 bytes (79.60%).
Recorded cost was 1,696 micro-USD, based on reported usage/charge; no price inference.

The first harness assertion expected JSON-only output and failed because the final
answer added prose before its correct JSON object. Inspection separately verified
all seven facts and the successful compaction boundary. Strict final formatting is
**not passed** by this test and remains C3.13/C3.14 work. The successful fidelity
claim does not erase that observation or claim lossless recall on arbitrary tasks.
Raw trace/summary/output remains ignored local data, not project memory.
