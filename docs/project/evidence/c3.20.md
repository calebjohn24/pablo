# C3.20 — Explicit Skill activation and selected resources

S02 implementation selects configured Skills through repeatable CLI `--skill` or
`options.skills.activate`, preserving locked overrides and physical root ceilings.
Activation sorts qualified identities and hashes metadata and complete SKILL.md
bytes separately. Only selected bodies enter ordinary task context; shared system
instructions stay stable. Compaction pins the task/activation prefix while reducing
completed history and retaining task-relevant resource facts.

The new `skill.read` capability uses admitted package directory handles, no-follow
component opens, regular UTF-8 files and bounded joined workers. Tool policy and
Skill root authority remain mandatory. Instructions cannot enable shell/MCP tools
or bypass filesystem write policy; scripts use the existing shell lifecycle.
The [contract](../contracts/c3-skills.md#explicit-activation-and-selected-resources-s02)
details limits, byte-count meanings, ownership and startup-error semantics.
