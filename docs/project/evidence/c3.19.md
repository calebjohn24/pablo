# C3.19 — Local Skill discovery

S01 adds bounded, explicit-root Agent Skills metadata discovery to Rust embedding
and offline CLI inspection. Activation and resource/model-context integration
remain C3.20. No live provider, remote installation or credential-file inspection
was used.

## Implementation and acceptance

- Pin the portable specification/reference validator at
  69ef37e9424c0a7ea9dd2293b559e43ec8176379, yaml-rust2 0.11.0 and Unicode
  normalization 0.1.25. Validate standard frontmatter fields, folded/quoted text,
  Unicode NFKC names and directory agreement. Scalars retain string values as in
  the reference StrictYAML parser. Unsupported YAML graph/type features,
  duplicate fields and nonportable fields fail with fixed error codes.
- Host-selected roots produce deterministic ROOT/NAME records, source-relative
  paths and SHA-256 frontmatter identities. No ambient .agents/skills lookup
  occurs. Qualified records survive cross-root ambiguity; short-name lookup
  rejects it. Same-root normalized duplicates are excluded. Metadata describes
  allowed tools without granting authority.
- Roots and descendants use no-follow directory descriptors and regular-file
  checks before/after opening. Symlinked roots, packages and SKILL.md files,
  traversal, FIFOs and oversized frontmatter reject. Enumeration and metadata
  consumption have hard aggregate limits, cancellation and deadline checks.
  Synchronous work has no detached worker to outlive discovery. Host isolation
  remains necessary against arbitrary concurrent filesystem mutation.
- Six focused Rust tests exercise portable metadata, malformed YAML, explicit
  catalogs, body/script exclusion, root and file escapes, normalized duplicates,
  ambiguity, cancellation, expired deadlines and metadata/catalog/entry/diagnostic
  bounds. A large-file fixture crosses the aggregate byte limit without exceeding
  the per-file cap. A separate fixture exceeds the admitted Skill count.
- CLI skills list/show uses explicit deployment roots and prints metadata JSON;
  config explain/render stays offline. The host test proves empty defaults,
  .agents/skills support, body-independent metadata identity, qualified/short lookup,
  source-relative path normalization, denied root ceilings, traversal rejection
  and operation without provider credentials. An additional Rust test rechecks
  changed task workspaces against host root ceilings and intersecting denials.
  Changed bodies never enter the
  catalog and bundled script content is never executed.
- Deployment c3.19 adds options.skills.roots and authority[].skill_roots, reusing
  portable Path references and existing composition/provenance. Each authority
  layer intersects root containment, including after task-workspace rebasing.
  Empty roots take an early path to preserve unused-capability performance.
  options.skills.activate remains explicitly unavailable until C3.20.
