# C3.36 idempotent one-line installer

Date: 2026-09-15

## Behavior

Repeating the no-argument one-line installer is now a successful no-op when `$HOME/.local/bin/pablo` is already owned by a valid installer receipt for the same version and native target and the binary still matches the receipt's SHA-256. It prints the installed path and changes no files.

The narrow no-op does not weaken collision safety. It is disabled for `--archive`, `--replace`, and `--update`; a missing, symlinked, malformed, changed, different-version, or different-target receipt does not qualify. Explicit `--update` continues to refuse the already-installed version, and unowned files still require deliberate replacement.

This host already had the exact frozen `v0.0.1` arm64 Mac candidate at `$HOME/.local/bin/pablo`, with its installer receipt and expected SHA-256. Piping the reviewed updated script through `sh` returned success with “pablo 0.0.1 is already installed” and the binary continued to report `pablo 0.0.1`.

## Verification

- `sh -n install.sh` passed.
- `npm run test:release` passed seven tests. The default piped-install case now repeats the argument-free command against the receipt-backed fixture, observes a successful no-op and proves the original executable remains unchanged. Existing checksum, collision, update, replace, changed-binary removal and deterministic-package cases still pass.
- `cd website && npm test` passed all eight site/content/release-route checks after the README and public installation guides documented the repeat behavior.
- `cat install.sh | sh` passed against this host's unchanged receipt-backed `v0.0.1` installation, followed by a successful `pablo --version`.

After PR #56 merged and production Docs deployment `34918573635` passed, the exact public command `curl -fsSL https://runpablo.pages.dev/install.sh | sh` returned success against this host's existing receipt-backed installation. It reported `pablo 0.0.1 is already installed at /Users/caleb/.local/bin/pablo`; the installed binary then passed `pablo --version` and the offline `pablo demo`. This confirms the production script serves the reviewed idempotent behavior.
