# C1.3 follow-up: defaults and call budgets

The user reported an ACP run ending with two bare `shell.run` messages and `limit_exceeded`, then selected Gemini Flash 3.8 and requested no default tool-call budget. The original run had no retained trace, so its exact limit is unknown. This follow-up does not claim to reproduce that live response.

## Changes

- CLI and ACP default to `google/gemini-3.8-flash`, verified in the [official Vercel catalog](https://vercel.com/ai-gateway/models/gemini-3.8-flash). Explicit model overrides remain available. The live smoke helper now reads the actual model from its native trace instead of labeling every run GPT-4.1 mini.
- Core, CLI and ACP default to unlimited model/tool call counts. Optional Rust `RunLimits` fields accept `None` for unlimited and `Some(N)` for a cap; JSON accepts null/omitted fields or numeric caps. `--max-tool-calls N` and `--max-model-calls N` expose these settings to users, including zero to disable those calls.
- Removed the prompt's obsolete two-tool/four-model restriction. With explicit caps, the adapter requests `tool_choice: "none"` when another tool result cannot be consumed. The stable tool/instruction prefix remains intact and hard runtime enforcement still rejects a provider that ignores the hint.
- Reference client diagnostics show actual commands/cwd, terminal tool status, exit code and output sizes, and exact native limit/policy/failure details on both prompt results and JSON-RPC errors.
- D014/D015 and the cycle plan record the user's changed defaults. Existing timeouts and size/event/transport bounds remain; unlimited here means call counts. Native event and ACP outcome shapes remain unchanged.
