# Legal benchmark cost diagnosis and proposed fix

2026-09-29. User-requested analysis, not runtime implementation or completion of
C3.36. Inspected Pablo source at `87cc3fec71088f9339dd62b9ee638af350b8ba0d` and
the retained `legal-synthetic-v1.0` results in the sibling `legal-benchmark`
workspace. No paid calls or credential reads. Aggregate input identities and
trace reconciliation are in [the analysis artifact](c3.36-legal-cost-analysis.json).

## Finding

The Opus comparison is the relevant cost regression. The GLM configuration is
already the cheapest system in the final scorecard. All three Opus configurations
completed 50/50 tasks, without retries. Pablo's costs are catalog estimates;
Claude Code and SDK costs are client-reported, not independently verified bills.

| Opus system | Cost/task | Input cost, 50 tasks | Output cost, 50 tasks | Output tokens/task | Tools/task |
|---|---:|---:|---:|---:|---:|
| Pablo / Vercel | $0.16560 | $4.83054 | $3.44953 | 2,759.62 | 8.04 |
| Claude Code / Anthropic | $0.11200 | $2.01459 | $3.52953 | 2,823.62 | 8.00 |
| Agent SDK / Anthropic | $0.09388 | $1.59923 | $3.03893 | 2,431.14 | 8.00 |

Pablo costs 47.9% more than Claude Code and 76.4% more than the SDK. Against
Claude Code, input accounts for $2.81594 excess while output offsets $0.08000.
The native client's reported total also exceeds this reconstructed subtotal by
$0.05581. Against the SDK, input accounts for 90.1% of the reported difference,
output for 11.5%, and its $0.05578 residual offsets 1.6%. The reconstructed
components clearly point to input cost, but do not fully reconcile native bills.
Provider billing detail or richer usage is needed to explain these small residuals.
These are decompositions at the benchmark's historical rates, not causal
estimates of what a new implementation will save.

## Runtime causes and accounting limitations

**Missing explicit caching is the primary actionable cause.** Pablo sends
string messages without cache markers or the gateway automatic-caching option
in `crates/pablo-core/src/gateway.rs::request_body`. Its 233 model calls report
966,107 total input tokens, zero cached reads, and unknown cache writes.
Claude Code reports 1,496,777 cache reads plus 202,207 writes; the SDK reports
851,546 reads plus 187,413 writes. Anthropic's native input counter excludes
cache tokens, so adding its three categories is required before comparing
token volume with Pablo's inclusive Chat Completions counter.

[Vercel's documentation](https://vercel.com/docs/ai-gateway/models-and-providers/automatic-caching)
confirms that absent a caching option it passes requests through, whereas
Anthropic needs markers. The same page documents automatic caching for Chat
Completions and a session-affinity header. This makes missing cache enablement
a strong diagnosis; normalized zero reads alone would not prove an actual
billing miss because upstream usage can be incomplete. Retained raw traces are
native events, not raw HTTP usage bodies, so they cannot settle that ambiguity.

**No retry storm or tool-error loop was observed.** All 233 model calls and 402
tools completed. Tools were 250 reads, 50 listings and 102 writes. Input/output
token sums reconcile to all 50 terminal envelopes. Pablo averages 4.66 model
calls; the roughly eight tool calls are comparable to both competitors. Some
turns already batch several tools despite the wire `parallel_tool_calls:false`.
Changing concurrent tool execution is not the first fix.

**Output volume is secondary.** Pablo generated fewer output tokens than Claude
Code. Against the SDK it generated 328.48 extra tokens/task, worth $0.00821/task
at the retained output rate. Middle model turns produced 114,466 of 137,981
output tokens, mainly file-writing/tool arguments; final replies were only
17,865 tokens. Tightening final prose alone therefore has limited impact.
Pablo reports 20,902 reasoning tokens, included in output rather than an extra
billable category. Provider-default versus medium effort is unmatched; lowering
effort requires a separate quality-controlled experiment.

**Cost observability needs repair.** The Vercel parser always sets cache writes
to unknown and does not populate actual dollar cost. In the benchmark,
`legalbench/adapters.py` recognizes numeric `cost_microusd`, but Pablo emits
decimal strings, so a future reported amount would be missed. Its fallback
estimator treats unknown token fields as zero and clamps inconsistent inclusive
input breakdowns rather than reporting an unavailable estimate. These do not
explain the currently retained zero-read arithmetic, but can misprice the fix.
Validate actual gateway usage field shapes before implementing write parsing;
do not copy an OpenRouter field name without evidence.

## Benchmark defects affecting cost per exact task

The current scorecard divides total cost by 28 exact Pablo tasks, 30 Claude Code
tasks and 26 SDK tasks. That denominator mixes substantive errors with output
format conventions that were never disclosed to the model:

- `approval_status_reason` is requested only as a string, but its key demands
  snake-case labels. All five corporate tasks fail this finding in every Opus
  system despite retained explanatory answers matching the governing facts.
- `deviations` and `response_omissions` similarly expect exact codes where the
  model can reasonably provide explanatory strings. Date suffixes and equivalent
  phrases such as “not applicable” also fail exact equality.
- `corporate-approval-04` is expressly an ordinary, non-related-party transaction,
  but its key labels the failed ordinary majority as
  `insufficient_disinterested_votes`. This is a generator/key defect requiring
  review, not a reason to teach the model that incorrect label.

Revise the fixture generator to expose every canonical enum/date format in
`task.md`, correct inconsistent keys, and version the suite. Keep old results
unchanged; any semantic regrade must be a separate, explained diagnostic. Use
cost per attempted/completed task as the primary cost metric until that review
is complete. A schema on Pablo's final response would not validate `answer.json`
written by a filesystem tool; validation must target the actual artifact.

## Proposed implementation and acceptance

1. Add a typed provider caching policy with provider-default and automatic
   choices, propagated through CLI/deployments/model profiles. For Vercel Chat
   Completions, the documented request addition is
   `"providerOptions":{"gateway":{"caching":"auto"}}`. Select automatic in
   the Opus benchmark profile; avoid model-name heuristics and preserve the
   existing unspecified behavior elsewhere. Unsupported explicit settings must
   fail locally rather than vanish. The policy is provider-managed caching,
   not local response reuse.
2. Preserve stable message/tool prefixes. Add optional opaque per-run
   `x-session-affinity` only after cache enablement is measured, if locality is
   still a problem. Keep it stable across one run and isolated across runs.
3. Fix cache-write and dollar-cost observability using validated provider
   fixtures, distinguish absent from zero, and make the benchmark accept valid
   decimal accounting strings. Estimate only from complete, consistent usage
   and a recorded rate table; retain provider-reported and estimated fields
   separately. Test inclusive Chat and exclusive Anthropic input conventions.
4. Test request serialization, unsupported settings, streamed usage, fallback,
   privacy and cancellation offline. Then run a small matched cache-on/off Opus
   pilot, followed by the same 50 tasks with three repetitions if effective.
   Hold model, provider route, reasoning, output allowance, source hashes and
   task order constant. Separate cold and warm cross-task cache effects. Compare
   factual/citation accuracy, completion, mean cost and latency; do not promote
   solely from an estimated bill or a better strict-format denominator.

An illustrative within-task cache scenario using the retained token volumes
would write 318,094 unique prefix tokens and read 648,013 repeated prefix tokens.
At the historical rates that gives $5.76162 total, or **$0.11523/task**, a 30.4%
reduction from $0.16560. This assumes eligible append-only prefixes, successful
hits and unchanged generation. Traces do not expose token-level prefix identity;
tool-choice changes, routing and incomplete write reporting can break these
assumptions. It is a planning scenario, not a promised saving or measured result.

The first change should be cache enablement plus truthful accounting. Native
Anthropic transport, aggressive compaction, lower reasoning and cheaper-model
routing can be evaluated later if a matched caching run leaves a material gap.
