# C3.12a — Basic context compaction

CP01/CP02 implements the user-requested basic C3 compaction boundary. The
[contract](../contracts/c3-compaction.md) was frozen before implementation; the
[scope review](c3-compaction-scope.md) records the local Codex inspiration. Product
context and reviewed hash are unchanged. No dependency or provider-default change.

## Implementation and acceptance

- Deployment revision `c3.12a` adds typed context settings and optional per-profile
  declared capacity. Unknown capacity remains explicit. Import/override/unset,
  offline schema validation and render/reload preserve exact profile capacities.
  The production golden was refreshed from actual offline `config explain`;
  changes are new defaults/provenance and resulting fingerprints only. Its effective
  fingerprint is `sha256:07bd7a25edbd738a01dd2ff131473de4104a910736c9ed6daf0098f3de208987`.
- The runtime estimates full logical request bytes plus framing/tool costs and
  calibrates conservatively from reported input usage per exact selected profile.
  Integer arithmetic saturates safely; missing capacity/usage is never zero.
- One summary request on the selected model excludes retained recent complete
  turns, disables tools and spends normal root calls/time/tokens/cost. A smaller
  validated candidate retains the original task, unchanged prefix/tool catalog,
  labelled derived summary and recent complete tool pairs/private continuation.
  Completed effects and tool IDs remain settled; history replacement follows an
  accepted compaction-finished event with no intervening await.
- Bounded explicit machine-code HTTP/SSE overflow classification allows at most
  one recovery on the same selected entry. Summary and recovery never route-fallback.
  Oversized errors and freeform matching text remain provider rejection. A second
  overflow or partial answer stops explicitly. No live gateway wrapper acceptance
  or semantic-summary quality is inferred from synthetic fixtures.
- Native and negotiated ACP metadata expose identity, trigger, exact decimal size
  counters and discarded-history hash. Summary text is excluded from ordinary answer
  deltas, private continuation never appears in either capture policy, and OTel
  contains metadata only. Summary model span parentage matches the compaction span.
  Task envelope remains `c2.3`; non-negotiating peers retain prior shapes.

## Behavioral proof

`crates/pablo-core/tests/compaction.rs` proves real file-history threshold/overflow
continuation, prefix/task/recent-pair retention, shared calls, reduction, summary
suppression, invalid output rejection and OTel correlation. Runtime unit tests
exercise original-history/ID preservation on no history, insufficient input room,
call/token/cost admission, non-shrinking summary, provider error, cancellation,
deadline and failed closing-event delivery. Calibration is isolated and overflow-safe.

`tests/compaction.test.ts` exercises all three adapters through the CLI and fresh
ACP sessions, including retained opaque Open Responses state and actual file-write
side effects. Nine additional routed CLI/ACP cases cover freeform/oversized errors,
partial output, no history, repeated overflow, failed summary/recovery, streamed
machine codes and nested errors; both negotiated and ordinary peers are checked.
A configuration test covers composition, per-entry capacities, unset, rendering and
invalid bounds. Summary/recovery request counts and no secondary-entry dispatch are
asserted. Synthetic loopback credentials only; root `.env` is never loaded here.
