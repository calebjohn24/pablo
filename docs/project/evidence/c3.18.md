# C3.18 — MCP host integration and failure proof

M04 wires fresh async MCP admission into the built CLI and ACP worker. Provider
and exporter reuse never retains MCP catalogs, connections or authentication.
This checkpoint uses synthetic local providers and independent MCP peers; it does
not claim live remote/TLS acceptance or inspect the root credential file.

## Behavior and proof

- CLI establishes provider/exporter/trace/signal handling before launching MCP.
  ACP session creation admits exact host definitions offline; prompt admission
  revalidates the selection against current configuration. Empty client lists use
  host defaults; nonempty lists select a subset. Denied/unconfigured/changed
  definitions reject before launch. A marker executable proves an unselected or
  denied server never starts. Denied tools stay out of provider catalogs and never
  receive calls, while admitted discovery connections still close.
- Each CLI/ACP task discovers a fresh frozen catalog, resolves selected MCP secrets
  and awaits owned cleanup. Independent stdio reads prove actual file results reach
  the model and only explicitly selected credentials reach the subprocess. Python
  and macOS may synthesize LC_CTYPE and __CF_USER_TEXT_ENCODING under an empty
  environment; the fixture permits only those plus its selected token.
- Independent stateful HTTP JSON and SSE peers serve CLI and two ACP sessions each.
  Rotating file credentials and changing evidence between sessions proves fresh
  authentication/results. Each task initializes, discovers, calls once and DELETEs
  a distinct session. No automatic replay or stale catalog reuse is permitted.
- Required startup failures prevent model dispatch; optional failures omit the
  server. Malformed/oversized catalogs, duplicate names, unsupported schemas and
  cursors fail admission. RPC errors, invalid results, unsupported content and
  progress overflow retain failed disposition. Tool isError remains recoverable;
  bounded ordinary progress succeeds. Recoverable MCP telemetry uses
  mcp_tool_error rather than the filesystem error label.
- CLI SIGINT and ACP cancellation join active stdio process groups before return.
  ACP stdin EOF, paused/resumed output and output disconnect settle under the
  existing finite backpressure/cleanup bounds. HTTP disconnect/cancellation expose
  remote_completion_uncertain through native traces and ACP tool results, send
  bounded cancellation and DELETE, and never replay or claim ownership of the
  remote server process. Startup cancellation is a pre-run config_mcp_startup
  error; active-call cancellation is the native cancelled outcome.
- The host-only fixture endpoint override requires configuration and synthetic
  provider mode. It validates existing HTTP server names, literal loopback HTTP
  and absence of user information/query/fragment before credential access/launch,
  including when the server map is empty. Duplicate mappings and stdio targets
  reject. Header scope includes the actual selected endpoint; normal config still
  requires HTTPS. ACP/model inputs cannot supply this bootstrap override.
- The pinned independent Python SDK is mcp 2.2.0. Real Collector 0.160.0 on native
  darwin/arm64 receives six tasks across CLI/ACP and stdio/HTTP JSON/HTTP SSE:
  24 spans, six logical MCP CLIENT spans, exact native IDs and timestamps, and
  actual tool context propagation. Content, provider/MCP/exporter credentials and
  HTTP session tokens are absent from metadata-only telemetry. Reproduce with
  node scripts/smoke-mcp-collector.ts after building the CLI and installing the
  pinned local fixture dependencies. Missing Python is a skipped gate, not a pass.
