# C3.13 — Final-output schema validation

J01 adds optional final-answer validation to direct Rust, configured/legacy CLI,
and negotiated ACP. The separate C2 task envelope remains the transport contract.
The [frozen contract](../contracts/c3-output-validation.md) defines the supported
Draft 2020-12 subset, annotation-only `format`, exact bounds, failures and privacy.
C3.14 retains ownership of repair; this checkpoint makes no repair call.

## Implementation and behavior

- Admit bounded inline or regular-file schemas before dispatch, reject unknown
  assertions/external retrieval/cycles, resolve local `$defs`/`$ref`, and pin files
  into canonical inline deployment configuration before fingerprinting/rendering.
  Authorized locked overrides retain the exact schema and only narrow work.
- Reuse a 16-entry successful compilation LRU. Canonicalization explicitly sorts
  object keys, including when dependency feature unification enables
  `serde_json/preserve_order`; array order remains significant.
- Bound schema bytes/nodes/depth/reference expansion, final JSON bytes/nodes/depth,
  and weighted validation work. Charge comparison payload sizes as well as visits,
  so a large enum or required list cannot masquerade as one unit of work. These
  are finite synchronous work bounds, not a strict millisecond scheduling guarantee.
- Preserve the admitted schema instruction across tool use and stronger compaction.
  Validate only the final answer; non-JSON compaction summaries are not final output.
- Schema-enabled task revision `c3.13` distinguishes provisional/unvalidated,
  valid and invalid output. Local failure is `output_validation_failed`, with at
  most eight value-free diagnostics, bounded paths and 2048 diagnostic bytes.
  `structuredOf` parses only validated terminal output. Ordinary tasks and
  unnegotiated legacy task peers retain `c2.3`; generic ACP remains standard.
- Root output limits, cancellation/deadline and provider failures keep their
  original outcomes. In the over-budget delta fixture, Open Responses emits its
  existing `malformed_stream` before core byte accounting; gateway adapters emit
  `output_bytes`. Both retain unvalidated status. No adapter-normalization claim.
- Native metadata shares the runtime lifecycle. OTel exposes digest/status/error
  count/work only; redacted JSONL removes diagnostic paths, and trace admission
  reserves additional terminal metadata capacity for schema-enabled tasks.

## Performance

See [sanitized measurements](c3.13-measurements.json) for sequential matched
30-sample runs after five warm-ups. The baseline binaries are merged C3.12b;
current measurements include ordinary configured work, validated JSON through all
three adapters, and a matched filesystem pair. The structured harness checks
terminal validity on fresh and reused ACP sessions while preserving two model
calls, one real shell command, and 32 output deltas. JSON framing is extra payload;
this is a whole-workload comparison, not isolated validator timing.

follow-up and one reverse-order ordinary pair. No builds or tests ran concurrently
