# C3.22 partial — Prepared child capability scope

`PreparedRun::prepare_child` now derives one depth-one run from the parent's
admitted catalog and deployment. It accepts only selected task/overlay/attachments,
keeps trusted instructions and the canonical workspace, applies inherited child
limits, and rejects serialized input expansion beyond the child bound. It starts
no provider or external capability. A prepared child cannot prepare a descendant.
Child preparation leaves the trace path unset for root-owned delivery and never
reopens the parent's trace path.

The immutable child scope contains exact tool identities, selected approved Skill
names, inherited MCP descriptors and an exact ordered model-route subsequence.
Provider bootstrap and scoped credential lookup use the prepared run's effective
route. The approved deployment remains the host configuration; a separate host
bindings fingerprint includes child scope/limits/server selection so cached root
resources cannot satisfy a differently scoped child run. Deployment, command,
filesystem, provider and credential authority are inherited unchanged.

The tool factory removes executable entries as well as descriptors. Skill
instructions can remain ordinary task context when skill.read is excluded; the
retained package handles do not make that tool callable. Child Skill names must
select an approved root/package, including root tool-name ceilings for resource
access. Actual discovery/activation remains bounded, fresh and joined before
provider dispatch. This supports child-only activation without loading bodies
into the parent.

MCP selection cannot restore a server excluded by the parent, even through a later
ACP client selection. Each child factory creates fresh authentication/catalog
ownership. It admits only selected inherited tool identities and checks their
model-visible description/input schema against the parent snapshot. A changed
selected definition or missing explicitly selected tool fails before dispatch;
cleanup joins the new session even for an optional server. New unselected tools
are omitted. Session ownership survives tool filtering so close still joins it.
