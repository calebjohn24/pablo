## HTTP experiment

Two optimized binaries built from the same reasoning implementation: ordinary features versus `--features reqwest/http2`. Cargo's stale cached h2 index initially prevented the experimental build; an explicit registry metadata refresh resolved it without changing the pinned runtime dependencies. The default manifest and lockfile remain unchanged.

Twenty-four serial text-only calls use GLM Flash and Astra on OpenRouter, explicit low effort, the same prompt, six alternating pairs per model, and a fresh process per call. All 24 completed with the expected answer and known reported costs. Native diagnostics confirm actual HTTP/1.1 versus HTTP/2 negotiation; local fixtures separately verify HTTP/1.1 fallback and client reuse.

| Model | H1 p50 / p95 | H2 p50 / p95 | Median gain |
|---|---:|---:|---:|
| GLM Flash | 408.61 / 1009.87 ms | 391.55 / 723.12 ms | 4.17% |
| Astra | 1261.12 / 2147.20 ms | 1238.65 / 1265.95 ms | 1.78% |

HTTP/2 adds 534,784 bytes to this binary and roughly 0.6 MiB sampled peak RSS in this microbenchmark. Total reported experiment cost: $0.01891. The small sample and cold-start tails do not demonstrate a robust application-level benefit. Keep the existing transport default; do not attribute header wait solely to the network. Raw local rows are under `.pablo/measurements/latency-transport/`; the reproducible experiment is `scripts/knowledge-work/transport.mjs`.

## Reasoning experiment — complete

The retained matrix ran six tasks × seeds 41/42/43 × three repetitions × five configurations = 270 attempts, serially and with rotated configuration order. Pablo GLM/Astra each compare provider default against low; Pi GLM uses low and the same privately reused OpenRouter credential. All builds and test suites finished before the retained measurements; subsequent test-only checks started after all 270 attempts finished. Raw artifacts stay in `.pablo/measurements/latency-reasoning/`; every failure and unknown metric remains visible.

All 270 attempts are retained; 268 completed. Each configuration has 54 attempts and 225 individually scored factual checks. Failed attempts contribute missing facts and remain in latency/cost metrics. No strict whole-task pass rate is used.

| Configuration | Facts (higher better) | Wall p50 / p95 seconds (lower better) | Peak tree MiB (lower better) | CPU p50 seconds (lower better) | Reported cost, 54 attempts (lower better) |
|---|---:|---:|---:|---:|---:|
| Pablo GLM, provider default | 222/225 (98.7%) | 18.49 / 75.18 | 31.25 | 0.089 | $0.109141 |
| Pablo GLM, low | 213/225 (94.7%) | 8.26 / 19.94 | 18.55 | 0.041 | $0.066294 |
| Pablo Astra, provider default | 220/225 (97.8%) | 19.58 / 30.92 | 34.50 | 0.129 | $4.431148 |
| Pablo Astra, low | 220/225 (97.8%) | 18.32 / 27.16 | 32.41 | 0.108 | $3.995740 |
| Pi GLM, low | 218/225 (96.9%) | 8.82 / 23.53 | 160.52 | 0.350 | $0.033872315 |

GLM low lowers p50 by **55.3%**, but fails the no-regression factual gates overall and for policy, handoff, incident and project planning. Astra low lowers p50 by **6.5%**, below the predefined 20% gate; its other numeric gates pass. Each Astra configuration completed 53/54; all other configurations completed 54/54. Neither candidate qualifies for a faster default. The generic explicit controls remain useful for caller-selected tradeoffs; no model-specific runtime branch or automatic promotion was added.

Pablo GLM low uses far less local CPU/RAM than Pi and is slightly faster here, but scores fewer facts and costs about twice as much. This does not establish a blanket quality or cost advantage. Total client-reported reasoning-matrix cost is **$8.636195315**; including transport trials, **$8.655105315**. These are reported costs, not reconciled invoices.

The six synthetic families reuse fixed task structures across seeds and repetitions; 225 checks are not 225 independent real-world tasks. Results do not establish general model quality. Models requested were `z-ai/glm-5.3-flash` and `openai/gpt-6-astra` on OpenRouter. Native model labels confirm requested configuration, not independent provider model attestation; unreported effective reasoning remains unknown. Provider routing, cache state and native harness prompts/tools remain sources of variation. Codex, Claude Code and Ori were not rerun in this follow-up.

## Where time went

The 1,049 Pablo model calls all negotiated HTTP/1.1. Median local request preparation was 71–80 microseconds, with p95 151–186 microseconds. Median first-data offsets were about 0.44 seconds for GLM and 0.87–0.88 seconds for Astra. Median model-call time accounted for 99.57–99.97% of native task runtime across the four Pablo configurations. These spans include remote waiting and stream generation; they do not isolate DNS, TLS or pure network delay. Pi does not expose equivalent internal timings and those fields remain unknown.

One GLM provider-default handoff took 155.68 seconds; a single model call took 143.01 seconds, while its first data arrived after 0.66 seconds. That call reported 11,518 reasoning tokens out of 11,756 output tokens. The matched low-effort task took 9.69 seconds. This supports extended reasoning/stream generation as the main delay in that case, rather than initial network wait. It does not prove the same cause for every model or task. Output accounting treats reasoning tokens as a subset, never an additional charge.

## Paired report-detail review

Reviewed every Pablo report slot for seed 41, repetition 0: six families × two models × default/low = 24 slots, comprising 23 reports and one missing report. This is an unblinded assistant review, not an independent human rating. It examines calculations, decision-relevant constraints, uncertainty, source grounding and proposed next actions. Exact citation-set diagnostics are not promoted into strict task passes.

| Family | GLM default versus low | Astra default versus low |
|---|---|---|
| Reconciliation | Low is shorter while preserving arithmetic, deduplication, status exclusions, credit/payment distinction and sources. Removed caveats are not needed for the supplied one-invoice-per-vendor data. | Both retain calculations, date-scope qualification, vendor-level allocation and the distinction between proposed payments and executed actions. |
| Policy | Low's report gives an incorrect approved amount for claim A while its own explanation computes the correct cap; the answer file repeats the error. Default is correct on the scored facts. | Both preserve date-sensitive rules, taxi cutoff, receipt condition and the potentially shared claimant/day allowance caveat. |
| Vendor | Low retains capability screening, signed setup-fee override, total cost, savings, budget and contract next steps. | Both retain the same decision-relevant numbers and constraints. |
| Handoff | Low retains current owners, dates, completed marketing, unresolved finance and source precedence. Default repeats more history and has a minor misleading description of a delayed deadline. | Low failed before producing a report; default preserves all current actions and unresolved ownership/date information. |
| Incident | Low retains the 12-minute window, request subtraction, unknown root cause and unconfirmed data loss. It proposes fewer follow-up actions. | Both distinguish correlation from causation and lack of evidence from proof of no loss. |
| Project plan | Low preserves the schedule, critical path, float and zero deadline margin. Default's scored answers are correct, but its prose contains inconsistent backward-pass labels/arithmetic. | Both provide consistent forward/backward schedules, slack, assumptions and deadline implications. |

Shorter reports can preserve the necessary detail, but neither effort setting guarantees narrative correctness. In particular, exact answer scoring misses the default GLM scheduling explanation defect. Report quality and completion must remain part of a default decision; this small qualitative sample does not establish broad equivalence.

Both missing handoffs are `meeting-handoff-s41-r0-pablo-astra-low` and `meeting-handoff-s43-r2-pablo-astra-provider_default`. In each, native tool metadata reports `output_limit`, 12,000 captured stdout bytes and truncation; source files total 12,236 bytes. Given the shell's `min(requested_capture, host_ceiling)` implementation and the unchanged 8 MiB host ceiling, this identifies a smaller tool-call capture bound. The current runtime turns that overflow into terminal `tool_output_bytes`. This is a model-plus-harness failure, not evidence that Astra could not answer the task. Both are retained without retry; recovery semantics are a separate [deferred contract](../backlog.md), not a mid-benchmark change.
