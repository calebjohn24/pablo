## HTTP experiment

Two optimized binaries built from the same reasoning implementation: ordinary features versus `--features reqwest/http2`. Cargo's stale cached h2 index initially prevented the experimental build; an explicit registry metadata refresh resolved it without changing the pinned runtime dependencies. The default manifest and lockfile remain unchanged.

Twenty-four serial text-only calls use GLM Flash and Astra on OpenRouter, explicit low effort, the same prompt, six alternating pairs per model, and a fresh process per call. All 24 completed with the expected answer and known reported costs. Native diagnostics confirm actual HTTP/1.1 versus HTTP/2 negotiation; local fixtures separately verify HTTP/1.1 fallback and client reuse.

| Model | H1 p50 / p95 | H2 p50 / p95 | Median gain |
|---|---:|---:|---:|
| GLM Flash | 408.61 / 1009.87 ms | 391.55 / 723.12 ms | 4.17% |
| Astra | 1261.12 / 2147.20 ms | 1238.65 / 1265.95 ms | 1.78% |

HTTP/2 adds 534,784 bytes to this binary and roughly 0.6 MiB sampled peak RSS in this microbenchmark. Total reported experiment cost: $0.01891. The small sample and cold-start tails do not demonstrate a robust application-level benefit. Keep the existing transport default; do not attribute header wait solely to the network. Raw local rows are under `.pablo/measurements/latency-transport/`; the reproducible experiment is `scripts/knowledge-work/transport.mjs`.

## Paired report-detail review

Reviewed every Pablo report slot for seed 41, repetition 0: six families × two models × default/low = 24 slots, comprising 23 reports and one missing report. This is an unblinded assistant review, not an independent human rating. It examines calculations, decision-relevant constraints, uncertainty, source grounding and proposed next actions. Exact citation-set diagnostics are not promoted into strict task passes.

| Family | GLM default versus low | Astra default versus low |
|---|---|---|
| Reconciliation | Low is shorter while preserving arithmetic, deduplication, status exclusions, credit/payment distinction and sources. Removed caveats are not needed for the supplied one-invoice-per-vendor data. | Both retain calculations, date-scope qualification, vendor-level allocation and the distinction between proposed payments and executed actions. |
| Policy | Low's report gives an incorrect approved amount for claim A while its own explanation computes the correct cap; the answer file repeats the error. Default is correct on the scored facts. | Both preserve date-sensitive rules, taxi cutoff, receipt condition and the potentially shared claimant/day allowance caveat. |
| Vendor | Low retains capability screening, signed setup-fee override, total cost, savings, budget and contract next steps. | Both retain the same decision-relevant numbers and constraints. |
| Handoff | Low retains current owners, dates, completed marketing, unresolved finance and source precedence. Default repeats more history and has a minor misleading description of a delayed deadline. | Low failed before producing a report; default preserves all current actions and unresolved ownership/date information. |
| Incident | Low retains the 12-minute window, request subtraction, unknown root cause and unconfirmed data loss. It proposes fewer follow-up actions. | Both distinguish correlation from causation and lack of evidence from proof of no loss. |
| Project plan | Low preserves the schedule, critical path, float and zero deadline margin. Default's scored answers are correct, but its prose contains inconsistent backward-pass labels/arithmetic. | Both provide consistent forward/backward schedules, slack, assumptions and deadline implications. |

Shorter reports can preserve the necessary detail, but neither effort setting guarantees narrative correctness. In particular, exact answer scoring misses the default GLM scheduling explanation defect. Report quality and completion must remain part of a default decision; this small qualitative sample does not establish broad equivalence.
