# C3.33 controlled concurrency observation

The final native-revision full Node suite passed 340 tests under serial file execution, with no failures, cancellations or skips (146.821 seconds). This includes cancellation, bounded input, maximum escaped output and stalled/resuming consumer cases. The earlier serial run also passed 340 tests.

A separate controlled stress run used `node --test --test-concurrency=2 tests/acp.test.ts tests/a2a-boundaries.test.ts tests/model-fallback.test.ts`, with no compilation or other test job running. It passed 103 of 107 tests and cancelled four in 498.971 seconds. R03 CLI cancellation before assignment exceeded its 15-second test deadline (32.670 seconds observed); ACP stalled output exceeded its 45-second parent deadline (57.910 seconds), cancelling its nested stall case; maximum escaped output exceeded its 30-second deadline (434.780 seconds observed). All fallback cases passed. This reproduces the class of observations retained in [C3.29](c3.29-node-triage.md); the cause remains unproven.

After that handle terminated, a focused concurrency-two run selected those exact parent scenarios in the ACP/A2A files, without changing assertions or deadlines. All five tests passed in 31.786 seconds. An ignored diagnostic preload sampled each Node worker's monotonic timer, CPU and RSS. In this passing run, maximum sampled timer intervals were 251.59 and 251.26 ms for a 250 ms interval; retained RSS samples peaked at about 109 and 135 MB. These passing-run observations do not explain or negate the failed broader run.

K01 functional conformance uses the explicitly serial commands in the operation matrix. Cancellation and slow-consumer acceptance pass there and in the focused concurrent run. Arbitrary concurrent test-file stress is not certified by this checkpoint. No timeout was raised and no assertion or required case was skipped. Native platform stress remains a disclosed limitation for any later release acceptance; the user-selected stopping point is C3.33.
