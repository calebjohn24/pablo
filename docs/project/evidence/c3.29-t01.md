# C3.29 — T01 basic streaming TUI

T01 passes. `pablo tui [TASK] [RUN OPTIONS...]` opens the bounded composer; bare
`pablo` selects it only for terminal stdin/stdout with a usable TERM. Explicit
run/shorthand, JSON, ACP, help and inspection retain their existing surfaces.
The [contract](../contracts/c3-tui.md) freezes controls, selection and exit behavior.
C3.30 retains the full PTY stress/resize/tool/child/error-restoration matrix.

## Implementation and behavioral proof

The TUI and CLI share `run_options`. Each submitted task supplies fresh input and
a real cancellation token to the same preparation, provider, tool, supervisor,
trace and cleanup path. UI state never becomes task context or authority. No
credential resolver, provider loop, saved chat or approval system was added.

A synchronous native-event projection retains 64 KiB of narration, seventeen
activity entries and sixteen Skill names with bounded labels. It shows root
provider/model, tools/owned agents, Skills, observed local usage, static-policy
status and native trace ID. Root terminal accounting supersedes observed counters;
unknown totals stay unknown. Queued stop/wait receipts clear activity even when
that child never emitted a run event. If a run returns without a delivered terminal
event, the display says that event is unavailable rather than remaining Running.

The renderer runs separately from the task future at at most twenty frames per
second. Owned nonblocking terminal I/O avoids a blocking input thread; read polling
is five milliseconds. Frame writes have a 500 ms bound and restoration writes a
250 ms attempt. Display failure cancels and joins the task. Enter submits, arrows
and deletion edit UTF-8, bracketed paste preserves newlines without submitting,
Ctrl-C cancels through the runtime token, and Ctrl-D exits after joining work.
SIGTERM also joins before exit. Terminal-control and directional override/isolate
characters in content become visible replacement characters. No tool arguments,
Skill body or credential is copied into the view.

Five Rust presentation/composer tests cover bounded Unicode editing and output,
malicious OSC/control/bidi content, fresh-task display reset, and native model/tool/
Skill/queued-child/usage projection without private content. The real macOS PTY
fixture runs both explicit TUI and bare-terminal selection on the debug build:
backward insertion, two successful independent requests, malicious streamed OSC,
provider/model/policy/usage display, a third real cancellation, exact exit status
and restored terminal attributes. Provider request inspection proves prior output
is absent from the next task's context. Redirected no-argument help, explicit TUI
rejection and unchanged offline CLI output pass. The frozen release repeats the
explicit PTY fixture; [receipt](c3.29-pty.json).

Early PTY work exposed two distinct issues. Async `/dev/tty` reads returned EINVAL
on macOS; the implementation now opens the actual matching terminal device and
uses bounded nonblocking reads/writes. The initial harness stopped draining output
during exit and queried a terminal after its controlling owner had exited. It now
keeps an owner alive, drains throughout exit, and compares attributes after a
canonical handoff clears macOS's kernel-owned PENDIN retype state. No configured
flags are masked out. The two stalled test owners were explicitly terminated;
their owned child processes were subsequently observed gone. These findings do
not substitute for C3.30's comprehensive restoration proof.
