# C1.3 generous capacities

The user requested generous timeout and size defaults, followed by a commit of all existing changes. This is a follow-up to C1.3; live C1.4 acceptance remains pending.

## Defaults

| Capacity | Default |
| --- | --- |
| Model/tool call counts | Unlimited; explicit caps remain available |
| Run deadline | 1 hour |
| Shell deadline | 15 minutes, bounded by the remaining run deadline |
| Combined input/instructions; tool arguments | 1 MiB each |
| Serialized tool result | 8 MiB |
| Model output | 4 MiB per model call |
| Requested output tokens | 65,536 per model call |
| Serialized context | 32 MiB |
| Native events; normalized items per model call | 1,000,000 each |
| Optional native trace | 256 MiB |
| Gateway SSE frame; request/response | 32 MiB; 128 MiB each |
| Gateway SSE frame count; tool indices per response | 1,000,000; 128 |
| Gateway connection establishment | 60 seconds, bounded by the run deadline |
| ACP line; cumulative incoming bytes | 32 MiB; 64 MiB |
| ACP rendered prompt | 1020 KiB, reserving 4 KiB for instructions |
| ACP stalled write | 30 seconds |

`--timeout` and the new `--tool-timeout` accept 1–86400 seconds on CLI and ACP. Tool-provided timeout/output overrides can narrow host limits. The short process cleanup and SDK shutdown allowances remain independent of task execution deadlines. ACP still uses an eight-event queue, one outstanding notification and 128-message ingress bound.

Transport sizes cover larger tool results and the worst-case escaping of the default model output. Limits remain finite and enforced. No credentials, trace contents, or build output are included in this evidence.
