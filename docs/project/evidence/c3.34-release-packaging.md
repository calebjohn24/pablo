# C3.34 release packaging

This slice adds deterministic release packaging around the previously verified installer. `scripts/release/package.mjs` resolves the target-filtered, locked Cargo dependency closure; deduplicates bundled license and notice texts by SHA-256; and writes the executable, project notice, third-party inventory, and source/build/target manifests beneath the exact versioned root expected by `install.sh`. Its ustar entries have lexical order, root ownership, fixed modes and the source commit timestamp; gzip metadata uses a zero timestamp. Every archive receives an adjacent checksum.

`scripts/release/verify.mjs` checks the checksum and exact filename before extraction, rejects unsafe or multi-root paths and symlinks, validates required files and manifest identities, verifies the binary and license hashes, and optionally executes the candidate. `scripts/release/index.mjs` requires one native-built archive for each of the four supported targets, proves common source/tree/fingerprint/lock identities, flattens the set, and emits `SHA256SUMS` plus `release-manifest.json` with native acceptance still false.

The manually dispatched release-candidate workflow uses current native GitHub runner labels for macOS arm64, macOS Intel, Ubuntu 22.04 arm64, and Ubuntu 22.04 x86_64. It builds with Rust 1.98.1, Cargo.lock, the exact target triple and explicit macOS deployment target, records the runner image and dynamic dependencies, packages and executes each candidate, installs it under an empty prefix with a minimal environment, runs the offline demo without Node/Python/source, removes it, preserves an unrelated prefix file, and uploads both individual candidates and their common index. Actions are pinned by commit. Cross-compilation is not used or credited as native acceptance; the complete target suites remain C3.35–C3.38.

The installer now downloads from `https://runpablo.pages.dev/releases/<version>/`. A read-only Pages Function validates the version and filename allowlist before reading the private `pablo-releases` R2 binding. Immutable cache and attachment headers come from the route. The production docs workflow creates the bucket if absent before deploying the binding. R2 remains private; no `r2.dev` development endpoint is used.

Local verification passed six combined packaging/installer tests. The tests create the complete four-target set from fixed inputs, prove byte-identical repeat packaging, validate the combined index, execute the host fixture, exercise installation/removal, and reject checksum corruption, collisions, unsafe replacement and changed-binary removal. The website build passed six tests including allowed, mismatched, traversal, method and HEAD behavior for the R2 route. A real release-profile macOS arm64 binary was packaged with 271 target dependencies, verified and executed, installed under a minimal environment, used for the offline demo, and removed. A second packaging run from identical actual metadata, binary, source identities and epoch produced identical bytes. These local archives use the dirty working source fingerprint and are verification fixtures, not release candidates.

Platform documentation now states macOS 11.0+ for arm64, macOS 10.15+ for Intel, and glibc 2.35+ for both GNU/Linux targets. macOS candidates are unsigned and not notarized; Linux candidates are unsigned and do not support musl. The root NOTICE deliberately grants no Pablo project license and points to the generated third-party inventory. Selecting a public project license remains an owner release decision outside this packaging mechanism.

Wrangler 4.92.0 compiled the Pages Function and generated its release route successfully. The four-target workflow and Cloudflare provisioning have not run yet because a newly added dispatch workflow must first exist on the default branch. C3.34 remains in progress until that workflow produces and verifies the common candidate set and the Pages deployment proves the private R2 route in production.
