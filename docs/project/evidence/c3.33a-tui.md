# C3.33a — TUI flicker, history and Markdown fixes

User requested fixes for flickering, missing tool/chat history, and Markdown formatting after the C3.33 stopping point. This follow-up does not start packaging.

## Behavior

The previous renderer cleared and repainted the entire screen every 50 ms. The new renderer caches display revisions, skips unchanged layout and emits only changed rows. Paints use synchronized-output markers where supported; restoration also resets synchronized output, styles and mouse modes. There is one full clear on entry and zero idle output.

Visible prompts, assistant text and terminal outcomes survive subsequent task submissions within the current terminal session. Tool starts and completions become persistent transcript entries with name, call ID and status, including calls that finish between refreshes. Per-task metadata still resets, and each native task has fresh execution context. Display retention remains capped at 64 KiB with an explicit oldest-text-discarded marker.

Page Up/Down, arrows and mouse wheel navigate retained history while idle or running. Ctrl-Home reaches the oldest retained text; Ctrl-End returns to the latest output. New output preserves the scrolled viewport during ordinary streaming. Submitting a task returns to the live tail.

Basic Markdown supports headings, bold/italic/strike emphasis, bullets and ordered-list text, quotes, links with URLs, and inline/fenced code. Wrapping excludes renderer-owned ANSI bytes from column counts. Original terminal controls remain neutralized; no dependency or alternate model loop was introduced.

## Verification

- The saved C3.33 release fails the new regression at `idle renderer emits repeated output`, reproducing the flicker mechanism. The new release passes it.
- `cargo test --locked -p pablo`: 51 passed, four existing ignored. Seven focused TUI tests cover bounded/control-safe text, fresh metadata with retained history, tool/child/usage presentation, composer editing, Markdown styles/wrapping, anchored scrolling and changed-row/idle painting.
- Debug and final release `tests/tui.test.ts`: 14 passed each, no skips/cancellations. Real PTYs cover streaming, rapid tools, prior-task history, Markdown cell styles, mouse and in-flight scrolling, zero idle bytes, exactly one clear, independent runtime context, cancellation, EOF, errors, resize, stalled output, child joining and terminal restoration. Ordinary redirected help/demo output remains clean.
- The slow-consumer fixture now sends continuously changing content; backpressure no longer depends on redundant idle redraws. Screen assertions interpret actual cursor/erase/SGR updates instead of treating every frame as a full clear.
- The first new display fixture reached its content/style assertions but timed out waiting for its PTY owner to exit. Draining the PTY while waiting, as in the existing harness, fixed that fixture lifecycle; the confirmation and final release suite passed.
- Final Clippy with warnings denied, typecheck, formatting, diff checks and the existing 102-file protocol pin audit passed. Project helper tests passed 34 cases.
- `cargo build --release --locked -p pablo --bin pablo` passed. The rebuilt executable is `target/release/pablo`, SHA-256 `39669a6c4e38421a5180ad2a55278a94d95a09a440a758adfc96c3365e1126d0`, 15,042,000 bytes (16,528 bytes above baseline).

These local synthetic samples include the 20 Hz render cadence; they do not measure live-model latency.
