# C3.36 user-directed Opus caching and cost follow-up

The user promoted the legal cost proposal on 2026-09-29, retaining C3.36 as the
active checkpoint. Existing RCA edits are preserved in this change. This follow-up
does not complete C3.36 native Linux interface, Collector or live acceptance gates.

## Implementation

Typed `PromptCaching::{ProviderDefault, Auto}` is opt-in via CLI, deployment root
model and named profile `model_options.prompt_caching`. Vercel Chat Completions
serializes the documented `providerOptions.gateway.caching=auto`; unsupported
adapters reject the explicit setting locally. Defaults omit the wire addition and
profile field. Configuration composition, override locks and fingerprinting use
the existing machinery. Ordinary requests, routes, repair, compaction and child
profile inheritance retain the setting. Model, reasoning, tool and output controls
are unchanged. Session affinity and native Anthropic transport remain deferred.

Native local diagnostics capture only validated `gen_<ULID>` IDs, at most 30 ASCII
bytes. IDs are excluded from OTel exports. Missing cache writes and dollar costs
remain unknown. The sibling runner's reproducible patch and input/output hashes
are in `docs/project/fixtures/opus-cost/`. Its billing pass runs after attempts,
with five bounded polls and 20-second HTTP timeouts, retaining unknown records.
Catalog estimates require complete consistent token breakdowns and use separate
fields from provider-reported costs. Cost per attempted task includes failures.

The unchanged suite remains `legal-synthetic-v1.0`; no task, prompt, key, scoring
or historical result changes are included. Enum/key defects remain in the backlog.
