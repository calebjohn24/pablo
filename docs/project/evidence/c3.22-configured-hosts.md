# C3.22 follow-up — Configured CLI and ACP roots

Explicit `options.children.enabled=true` now installs one supervised root through
a shared RootFactory execution helper. The deployment contract revision is c3.22;
children default to disabled. Schema/default provenance and the production golden
were deliberately regenerated. The remaining unsupported-feature regression now
uses future diagnostics configuration instead of children.

Both hosts create root identity before tree trace setup. The helper claims one
TreeSink consumer, opens admitted root tools, attaches RootOwner, and concurrently
polls the root and original-child consumer. Cleanup closes the supervisor even if
runtime rejects the run before ownership is claimed, preventing an idle consumer
from hanging. Cancellation keeps setup/execution futures polled. Root MCP permits
remain owned through manager cleanup. Prepared children never create supervisors.
Options/Bootstrap are cloned only for configured supervised roots; child workers
retain the existing narrowed prepared-run path.

CLI machine output records only the root terminal. Child text is labeled on stderr,
while the root trace contains original child records plus root_seq. ACP projects
tree notifications into the root protocol session while preserving child session,
agent and run attribution in correlation metadata; prompt completion ignores child
terminals. Projected tree tool-call IDs are prefixed by agent ID so identical provider IDs cannot merge root and child tool updates; native call IDs remain unchanged. The public fixture intentionally reuses call IDs across agents and checks unique starts with matching updates. Tree traces stay open through child completion. Gateway aliases now
admit `subagent` and count its descriptor in the bounded catalog. The first public
fixture found that missing alias as a not-sent provider rejection; this was fixed
before acceptance passed.

The configured CLI/ACP fixture exercises model-triggered spawn, inspect, wait and
child filesystem read, then root completion. It verifies immediate queued handles,
no parent task in child context, no child's file transcript in parent context,
no child subagent tool, six aggregate model calls and four tools, per-agent native
sequences, contiguous root delivery sequence, child terminal before root terminal,
shared trace ID and causal parent tool span, distinct child run identity, root-only
TaskResult, and attributed child ACP updates delivered to the root session. A second
CLI fixture waits for an actively streaming child, stops it, and verifies its
settled Cancelled receipt, closed provider connection and child/root terminal order.

Workspace Rust tests passed 302 with 11 ignored. Explicit factory tests passed
three and child_admission passed seven: 305 distinct Rust tests, eight pre-existing
ignored cases unrun. Rebuilt Node tests passed 267, project tests 34, TypeScript and
all-target warnings-denied Clippy passed. The first workspace run compiled the old

used.
