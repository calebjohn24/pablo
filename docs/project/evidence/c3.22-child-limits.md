# C3.22 partial — Inherited child limits

C3.22 remains in progress; A02 and the supervised child path are not complete.

Review found that shared ledger registration checked only model/tool calls and
token/cost ceilings. Host-constructed child limits could widen duration, event,
byte, output-token or filesystem-work limits. Registration now rejects widening
or erasure in every RunLimits dimension before inserting the child. Exhaustive
destructuring requires an explicit decision when a new limit field is added.

`ChildCeilings::apply_to` derives limits from the admitted parent, preserving all
unselected fields. It applies the child input/context/result bounds, rejects an
explicit widening and validates canonical unsigned accounting strings even for
direct host calls. Zero accounting/call allowances remain zero. Unlimited model,
tool and filesystem-work defaults remain unlimited. This projection reserves no
resources, grants no capabilities and does not establish a new root deadline.
The supervisor still needs to connect it to complete authority admission.
