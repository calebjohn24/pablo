# C2.2 safe file mutations

Verified on macOS arm64 on 2026-09-05 UTC, continuing under the user's full-cycle authorization.

Implemented explicit `fs.write`/`fs.edit` capabilities through `ToolRegistry::configured_with_writes` and CLI/ACP `--allow-write`. A contradictory no-filesystem/write flag combination rejects configuration. The default remains reads plus shell, with no filesystem mutation capability. Write-root policy is enforced immediately; an explicit host deny overrides the opt-in. Replacement/edit also require read authority.

Mutations require null create-only or exact SHA-256 replacement preconditions. Edit replaces exactly one literal match without normalizing unrelated bytes. The worker validates the full prospective result before creating a private same-directory temporary file, writes bounded chunks, applies ordinary mode bits, then rechecks revision/policy/cancellation before atomic installation. Creation uses an atomic no-replace hard link and temporary-name cleanup; replacement uses rename. New files are 0600; ordinary permission bits are preserved and special bits cleared. No ownership/ACL/xattr/hard-link-identity, external-writer compare-and-swap or crash-durability claim is made.

Successful tool results retain `committed:true` after commit, including subsequent cancellation or cleanup failure. Precommit errors preserve the target and await cleanup. The runtime still owns sequential tool execution; hosts isolate independent runs/external writers. The system instruction now refers to available tools instead of requiring the shell-only capability; no model/provider routing or performance-driven prompt optimization was introduced.
