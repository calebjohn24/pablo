# C1.3 evidence: ACP process boundary

Environment: macOS / Darwin arm64, Rust 1.98.1, Node 24.20.0, npm 11.19.0. The initial C1.0–C1.2a files were committed as `3d64b7e` before C1.3 implementation. The reviewed context SHA-256 remains unchanged.

## Implementation and acceptance

- `pablo acp --stdio` uses official Rust SDK 2.1.0 with stable protocol v1, no unstable features, and the existing runtime/gateway/shell implementation. The TypeScript reference client uses official SDK 1.4.0. [Exact source/schema pins](../../acp-lock.json) and [the extension schema](../../pablo-acp-v1.schema.json) are part of the change.
- `initialize`, `session/new`, `session/prompt`, `session/update`, and `session/cancel` work through the actual executable. A process admits one session and one prompt. Optional capabilities remain false/absent, unsupported methods return SDK errors, and host-only fixture/provider settings cannot come from prompt metadata.
- The TypeScript HTTP/SSE fixture requests an actual shell read of a temporary synthetic evidence file, verifies the tool result in the next model request, and returns that evidence. It checks stable instructions/catalogs, ordered message/tool notifications, typed outcomes, one terminal response, valid protocol-only stdout, and native OTel identity correlation. ACP shapes validate against the pinned official stable-v1 SDK schema; negotiated metadata validates against the checked-in extension schema.
- Cancellation waits for the shell PID to disappear before responding and includes the terminal tool update. Tests also prove cleanup after stdin EOF, a broken stdout observed on a subsequent write, and SIGTERM while stdin remains open. A cancellation during final output draining returns ACP `cancelled` while preserving an already-settled native outcome.
- Slow-consumer fixtures send 60,000 control characters across bounded provider frames. A paused consumer fills the runtime queue, produces its bounded diagnostic, resumes with every character intact and coalesced ordered updates, or remains stalled until the two-second write deadline closes the process connection. Native terminal delivery remains observable in the local trace.
- Input tests cover 512 KiB frame overflow, missing newline, batch arrays, the 128-message connection bound, malformed JSON with SDK error recovery, and future fields. Additional tests cover version fallback to v1, resource references, wrong-session/idle cancellation, busy/repeated prompts, unsupported MCP/content, provider parsing failure, run deadlines and invalid host endpoints.
- The official Rust client independently initializes and creates a session over actual Unix pipes; Node executable fixtures use socket-backed subprocess stdio.
- Tests use synthetic credentials and loopback endpoints. The real root `.env` was never read by these checks. Trace artifacts are temporary local data; only this summary is retained. Default native content remains redacted and synthetic credentials are absent from wire/trace output.

## Corrections discovered during implementation

The first Rust build exposed changed SDK export paths, and the first TypeScript check exposed the SDK's context-object callbacks plus Node/DOM stream declaration differences. These were corrected using the pinned SDK source. One initial assertion expected an explicit `pending` tool status; ACP omits that default, so the fixture now interprets the standard default. The first late-cancellation fixture accidentally exceeded the gateway's existing 128 KiB SSE frame limit; it now splits its synthetic payload across three legal provider frames, preserving the intended blocked-output condition. All corrected checks pass.
