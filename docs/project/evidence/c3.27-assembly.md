# C3.27 increment — bounded remote lifecycle and SSE assembly

C3.27 remains in progress; full R02 and its merge are pending. This increment supplies the lifecycle/framing layer needed by production transport and supervisor integration.

`a2a::lifecycle` accepts freshly decoded and charged envelopes, preserves remote IDs, and materializes immediate Message or terminal Task results. It distinguishes remote failure, cancellation, rejection and input/auth-required states. Streamed artifact Parts append in order; replacement and full Task snapshots supersede earlier data. Last-chunk tracking, sixteen artifacts, thirty-two Parts per artifact and a 64 KiB serialized-result ceiling bound retained content. Invalid updates poison completion while preserving accepted state. Interrupted streams and incomplete artifacts cannot silently become successful results. File bytes and URL/filename references remain inert data.

`a2a::sse` handles byte-split UTF-8 BOM, CR/LF/CRLF, multiline data and comments. Raw framing, ignored fields and empty frames count against bounded frame/stream budgets; truncated data at EOF rejects. IDs and retry directives do not initiate reconnection. The new CPU benchmark measures framing plus complete result assembly, not only decoding.

The pinned Python SDK's task manager generates `assembly.json`; its JSONRPC/SSE server emits the same text/file/URL artifact in chunks. The explicit Rust test consumes actual HTTP chunks through the new decoder and lifecycle, compares the final artifact to the independently assembled SDK snapshot, and verifies original remote IDs and completion. The server observes eleven handler calls and is joined even after a failed assertion. An initial test placement accidentally included the new valid request between the unsupported-version request and its no-new-handler-call assertion; moving the new request after that assertion corrected the test without weakening version rejection.
