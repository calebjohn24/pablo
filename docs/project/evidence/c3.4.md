# C3.4: literal shell command policy

Q01 is complete on macOS arm64. The [contract](../contracts/c3-shell-commands.md) was frozen before implementation. Command rules are optional: every supplied ordinary/authority layer checks the canonical executable identity and exact/prefix argv, with deny precedence. The fixed `/bin/sh` launcher executes a constant positional-argument wrapper, so task command text is not interpreted again. Existing launcher policy remains independent. Without command rules, legacy shell interpretation remains available.

Deployment and Rust hosts also support non-secret environment defaults, exact allowed environment names and canonical cwd-root rules. Model environment values override ordinary defaults, while each authority name restriction intersects. Provider/exporter environment names remain forbidden. The configured environment enforces UTF-8 byte bounds; legacy shell validation is unchanged. All four filesystem work quotas remain unlimited by default (D038).

Schema version stays 1; contract revision advances to `c3.4`. Schema references, defaults, resolved fingerprint/source provenance golden, render/reload and CLI/ACP identity expectations move together. Old source presets require no conversion; rendered snapshots get new fingerprints. D040 records the decision; the product-context hash is unchanged. Shell setup reuses the existing compiled input validator rather than compiling it twice.

These are executable/argv rules. An allowed program can interpret arguments or create descendants. Hosts own isolation and stable executable trees between check and exec; this is not an OS sandbox, atomic executable lease, semantic Git-option policy or script-digest trust mechanism. No live provider or real credentials were used.

## Matched performance

[Checked-in measurements](c3.4-measurements.json) contain hashes, methods, sample counts and distributions. Sequential warm-cache runs used 30 samples after five warmups, with no overlapping builds/tests. C3.3 release pablo SHA-256 was verified before freezing the baseline. Release size grew from 11,115,104 to 11,197,856 bytes (+82,752, about 0.7%).

| C3.4 legacy | 14.648 | 8.383 | 10.317 | 7.992 | 8304 / 14208 |
| C3.3 configured | 18.236 | 8.467 | 9.364 | 8.162 | 15072 / 16400 |

| C3.4 restricted, absolute printf input | 23.887 | 14.366 | 15.350 | 13.430 | 15360 / 17072 |

The bare input benchmark uses shell-builtin printf in legacy/unrestricted mode and a checked external executable in restricted mode. The additional absolute-input pair isolates policy more closely: warm ACP changed -0.169 ms, cold CLI +0.691 ms and core +0.815 ms. Both paths execute the same explicit program/argv in that pair. The roughly 5 ms bare-input difference is largely attributable to external executable dispatch, rather than a default-path regression. These local samples do not establish a universal latency bound or speedup.

Configured filesystem tool p50 milliseconds, C3.3 → C3.4: read 0.172 → 0.165; list 1.405 → 1.415; search 2.821 → 2.577; replace 0.567 → 0.548; edit 0.467 → 0.471. No hard performance pass/fail ceiling was invented. The extra absolute-command flag changes the measurement harness/source fingerprint, not the measured release executable; each report retains its own identities.
