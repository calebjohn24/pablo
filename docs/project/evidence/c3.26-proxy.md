# C3.26 increment: configured card retrieval and remote proxy identity

C3.26 remains in progress. Named configured retrieval and proxy identity are implemented; remaining wire mapping/bounds proof must close R01 before C3.27 execution or a completed-checkpoint merge.

`ResolvedDeployment::resolve_a2a` selects only a configured name under intersected host ceilings, validates a running depth-zero parent, retrieves its public card without credentials/redirects, and returns a fresh owned local `AgentRef` with kind `remote_a2a`. The explicit fixture method substitutes only literal loopback transport after original configuration admission. Unknown names and invalid parents reject before HTTP. Admission creates no remote task, ledger registration or execution claim.

The proxy retains configured name, selected endpoint/protocol/binding, raw card digest and untrusted metadata. Remote context/task IDs begin absent. They are separate bounded fields (256 UTF-8 bytes each, nonempty, no controls), cannot replace a local session and cannot change once bound; failed observations leave both identities unchanged. The root ledger now stores each registered agent's kind instead of assuming every non-root is an ACP child. Execution/event attribution uses that stored kind and rejects a forged kind even when other IDs match.

The independent SDK HTTP test now exercises the configured path twice, verifies distinct local IDs with identical card digests and retained parent/root ownership, rejects unknown names/depth-two creation without extra requests, and checks remote-ID stability and root-ledger kind binding. Exactly two unauthenticated versioned GETs are observed, no task submission or private credential lookup. SDK process cleanup is joined. The TCP rejection fixture now reads complete bounded headers rather than assuming a single read contains a header.
