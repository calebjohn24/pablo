# C3.22 partial — Admitted child execution through typed ACP

The internal typed dispatcher can now bind a PreparedRun child scope to one
temporary ACP session. Shared initialize/new-session/prompt/cancel handlers keep
the admitted workspace, input, MCP selection and host-provided trace parent fixed.
They use the saved prepared scope instead of rebuilding from mutable configuration.
The standard stdio path retains per-session host preparation. Child prompt parsing
uses its admitted input bound; ordinary ACP keeps the existing 1020 KiB bound.

RootLedger::admit_child commits counter registration and initial capacity under
one mutex. Failed capacity admission rolls back registration without consuming an
identity or total-child slot. The internal dispatcher requires a prepared child,
atomically admits one active slot and transfers a shared reference to its unique
lease into the worker. The dispatcher retains the other reference through close.
Thus normal close holds capacity through the join, while abandonment cannot drop
capacity before the worker exits. This does not yet reserve process/MCP/context
or cumulative event/trace capacity.

Worker tasks now carry an optional root accounting scope into Runtime. Child
model/tool admission, settlement and mutation serialization therefore use the
existing shared ledger hooks. The root deadline also bounds capability startup.
The run's cancellation token propagates to the child without immediately closing
its typed delivery channel, allowing normal cancellation updates to drain. Explicit
dispatcher close cancels the task and closes blocked delivery/event channels.

Close stores its shutdown task and result behind an async mutex. Cancelling an
individual close caller leaves the same join available to later callers; concurrent
or repeated close cannot bypass cleanup. Closed state is checked under the shared
handler lock so close cannot race a task into re-preparation or submission.

Verification:

- Full workspace Rust suite passed 263 tests after the ownership change. Final
  typed-dispatch tests passed all three, including the strengthened cancelled-close
  proof. Child admission passed all seven with the independent MCP case explicitly
  included. Across these runs 264 distinct Rust tests passed; eight pre-existing
  ignored cases remain unrun.
- A real loopback provider receives only the selected inherited route and child
  input even after the source configuration file changes. Incorrect workspace and
  input are rejected; prompt metadata cannot replace the host trace parent. Shared
  root/child model counters exhaust the root allowance, and root cancellation closes
  the live provider socket before settlement. Concurrent closes join the worker and
  release the slot; the temporary dispatcher cannot create a second session.
- A gated worker proves dropped close callers retain the same shutdown task. Even
  after worker exit, capacity remains reserved until a subsequent close finishes.
  A concurrent ledger test admits exactly one child and verifies that a rejected
  contender leaves no registration, then succeeds after the first slot is released.

  Clippy with warnings denied, formatting/diff checks and debug/release builds passed.
  The earlier Node run also passed; it was repeated after the lease ownership change.
  Prior intermittent F03 observations remain deferred to C3.33, not declared fixed.
