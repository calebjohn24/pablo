# C3.34 installer update path

The user requested an upgrade utility while the release archive PR was under review. `install.sh --update` now upgrades to another exact version only when the selected prefix contains an unchanged regular `pablo` binary and format-1 receipt created by this installer. It verifies the installed hash and target before download, refuses the same version, then applies the ordinary HTTPS/checksum/archive/candidate-version gates. The existing binary is retained as a temporary rollback copy until the new receipt is installed successfully.

`--update` is mutually exclusive with `--replace` and `--remove`. The broader `--replace` behavior remains available for a user-reviewed regular file without a receipt. Removal continues to verify ownership and the installed hash. Public README, getting-started and installation documentation now distinguish update, replacement and removal.

The six combined release tests passed on macOS arm64. The happy-path test installs dev.1, refuses an implicit collision, upgrades through a verified receipt to dev.2, refuses a same-version update, explicitly replaces with dev.3, and removes it while preserving unrelated prefix content. The changed-binary test proves both update and removal refuse modified content. Shell syntax, site tests, project consistency and diff checks also passed.
