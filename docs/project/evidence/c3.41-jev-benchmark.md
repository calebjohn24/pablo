## Obvious routing probes

Nine fixed synthetic cases define three expected tiers before running either prompt. `probe-jev.py` caps each task at one model call, then checks the terminal selected route; the expected terminal outcome is the model-call limit. These probes do not execute the destination model and cannot demonstrate generation quality or multi-turn pinning.

- Baseline: 8/9 requests returned a selection; all eight matched the expected tier and exact model. One gateway rejection.
- Improved prompt, two repetitions: 16/18 returned a selection; all 16 matched. Two gateway rejections.
- Confirmation, two repetitions: 17/18 returned a selection; all 17 matched. One gateway rejection.
- The previously rejected invoice case also succeeded in three separate diagnostic calls. No retries were added to the runtime. Temporary status-only instrumentation produced no rejection and was removed; no private provider body was inspected.

The probe commands with gateway failures correctly exited nonzero. There were no observed wrong-tier selections among 41 returned choices, but four of 45 requests failed before selection. This is evidence of working classification with observed gateway availability failures, not a claim of perfect reliability or statistically improved accuracy.

The revised prompt gives explicit tier boundaries and examples, evaluates dependencies and ambiguity, discounts output formatting/domain/file count, and avoids inventing conflicts in unread files. No answer keys informed this change. The classifier timeout increased from 10 to 30 seconds after a real 10-second timeout; the overall task deadline stays 300 seconds.

Three separate destination smokes also completed through the local release: direct arithmetic selected GLM 5.3 Flash (20.8 seconds), a bounded deadline analysis selected Grok 4.6 (6.0 seconds), and distributed-system design selected GPT-6 Astra (24.9 seconds). Each used exactly one Jev call and one generation call, no tools, and a 2,048-token output cap. These demonstrate live destination connectivity and mapping, not task-quality scoring. A preliminary smoke used an unsupported CLI output-token flag and failed before admission; the corrected smoke set that cap in its temporary config.

## Full rerun

The brief-only rerun (`local-jev-full-r2-20260917`) was stopped at the user's request after 15 completed tasks, all routed to Grok and pinned. Its partial report remains separate.

Completed first pass: `local-jev-full-context-r3-20260917`, 50 attempts, seed 42, one repetition, serial execution, no runtime retries. The first 27 completed; the final 23 received `provider_rejected` during Jev evaluation and made no generation calls. The user requested more classifier context after reviewing the task sources. This variant includes all four source documents and the task brief in both classification and generation input. Contexts are 1,681–2,442 bytes; all 50 passed preflight validation under the 48,000-byte limit. Source-context tests prove answer-key exclusion, link/non-source rejection and refusal of oversized context without truncation. Inline sources change file-read needs and prevent direct timing/score comparisons with brief-only runs. Results live under the external benchmark's local `results/` directory. The runner wrote per-task model logs and final JSON, Markdown and CSV reports. First-pass factual accuracy is 50.0% and citation score 49.76%, including failed tasks as zero; among the 27 completed tasks, factual accuracy is 92.59% and citation score 92.15%. Fifteen tasks have all six findings correct. Median completed-task time is 62.35 seconds. All 27 selected Grok, with exactly one Jev call per attempt and zero model switches. There were 127 generation calls; 118 reported cache reads, totaling 171,648 cached input tokens. These observations do not guarantee future cache hits.

After the rejection burst, a small diagnostic and three of the failed tasks classified successfully with unchanged full context. A separate recovery pass for the 23 failed tasks (`local-jev-full-context-r3-recovery-20260917`) used the exact first-pass binary/config fingerprints. Two tasks completed with all findings correct; the remaining 21 again failed during Jev evaluation. Recovery remains a separate report and does not replace the first-pass failures. No additional benchmark retry was run.

A subsequent bounded diagnostic of the rejected discovery task captured **HTTP 503 from the Vercel evaluation endpoint**. Earlier traces retain only `provider_rejected`, so the exact status of each earlier rejection is unknown. Status-only instrumentation was removed and the debug executable rebuilt; the release executable stayed unchanged. No response body or credential was printed. The remaining limitation is observed gateway availability, not a demonstrated model-switch defect.

Across both passes, 29 distinct tasks completed, all on Grok. All 73 attempts had exactly one classifier call and all four source documents in their initial input. There were zero model switches, 136 generation calls and 185,472 reported cache-read tokens. The 21 remaining tasks have no selected generation model. All partial and failed results are retained. This is not a clean 50/50 live completion result.

The full-context run still selected medium for every returned choice, including simple checklist tasks. Inspection suggests the tier descriptions remain conservative for this catalog; the cheapest reliable tier has not been established by a controlled GLM/Grok quality comparison. The obvious probes demonstrate all three destinations can be selected, and the destination smokes demonstrate all three can execute through Vercel.
