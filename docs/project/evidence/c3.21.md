# C3.21 — Child contracts and typed ACP dispatch

A01 uses official stable ACP v1 values directly against shared handlers for
initialize, new-session, prompt and cancel. Stdio calls those same handlers and
retains SDK JSON-RPC framing. The internal dispatcher does not use SDK Channel:
inspection of pinned agent-client-protocol 2.1.0 showed that Channel still carries
JSON-valued transport frames. Direct request/response/update dispatch here has no
JSON envelope or request conversion. Provider HTTP encoding, native trace encoding
and JSON-valued ACP extension payloads keep their existing separate contracts.

The [child contract](../contracts/c3-children.md) freezes temporary identity,
immutable root/parent ownership, explicit enablement, depth one, two active children
at C3.23, total/queue/context/result bounds, spawn/wait-any-or-all/inspect/stop and
equivalent host operations. It defines atomic root reservations and per-child
ceilings, process/MCP/event/trace capacity, narrowed capability/model routes,
shared filesystem mutation serialization, attribution and joined root shutdown.
Public Rust contract types make identity runtime-owned, reject model-supplied
ownership fields, and bound selected context/handle lists. They do not implement
supervision or replace C3.22's authority intersection and ledger admission.

The direct path uses the same runtime worker/provider/fallback setup. Typed updates
have one channel slot and require acknowledgement of consumption before another
notification. Closing wakes an unacknowledged delivery and joins the worker.
Prompt forwarding errors now also cancel and await task settlement before clearing
session state. The owner must await dispatcher close; Drop only signals cancellation.
No delegation tool or capability is advertised. The unsupported children execution
gate now identifies C3.22. Deployment/native wire revisions are otherwise unchanged.
