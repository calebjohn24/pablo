# C3.30 — T02 real PTY lifecycle and restoration

The fixture drives the native Unix terminal client through real PTYs with isolated
synthetic HTTP/SSE providers and the pinned independent A2A SDK. It creates no live
provider requests and reads no root credential file. Runtime source is unchanged
from C3.29; fresh debug/release builds are used for acceptance.

## Behavioral coverage

The eleven lifecycle cases cover successful completion; Ctrl-C during a model,
shell tool, local child and remote child; Ctrl-D while a model runs; actual
zero-byte terminal input; malformed provider SSE; small/large terminal resize;
blocked rendering; and external SIGTERM. Every case edits UTF-8 input using home,
end, deletion and insertion, and proves bracketed pasted newlines do not submit.
T01's existing real-PTY test continues to prove independent successive tasks.

Assertions inspect native JSONL after cleanup, require exactly one root terminal
result with the expected typed outcome, and reject events after that terminal.
Child cases require exactly one child terminal result before root settlement.
The remote case observes exactly one actual CancelTask request at the SDK peer.
Shell cancellation records the real owned shell PID, proves it was running, and
checks it is gone after cancellation. Every case waits for Pablo and its PTY owner
to exit. Fixture HTTP handlers and remote peer are joined during fixture cleanup.

Terminal-mode comparison includes all original termios attributes; cursor,
bracketed-paste and alternate-screen restoration sequences must also be present.
Malicious streamed OSC clipboard, ANSI color, C1 CSI and bidi controls must never
appear as executable terminal content. Resizing down to 30x5 shows the resize
message; returning to 140x40 resumes the running transcript and controls.

The blocked-rendering case withholds output reads until the native trace records
cancellation, proving native cleanup progresses without draining the screen.
Draining then resumes through restoration. The actual-read EOF case sets raw
VMIN=VTIME=0, causing an empty read, and still requires restoration of the attributes
saved before Pablo starts. Ctrl-D has its own separate case. Permanently destroyed
terminals and SIGKILL cannot promise delivered restoration sequences.

## Fixture development findings

Initial shell/remote assertions used wire/debug labels instead of the actual
screen labels (`shell.run` and `Remote Some(Working)`). A configured-child case
also needed canonical macOS temporary paths, and buffered trace output must not
be used as a live readiness notification. These fixture assumptions were corrected;
readiness now observes the screen and final proof inspects flushed native traces.
No runtime assertions or deadlines were weakened.

The first shell-label failure's fixture cleanup killed Pablo before it could join
the shell. The identified orphan sleep was explicitly terminated and subsequently
observed absent. Failure cleanup now sends SIGTERM to Pablo and drains the PTY
while waiting for joined exit before any forced fallback. Final passing shell
cases independently prove the owned shell is gone.

## Native scope and reproduction

See the [TUI contract](../contracts/c3-tui.md#reproducible-t02-native-checks) for
commands, case names, fixture prerequisites and EOF/backpressure techniques. This
acceptance is macOS arm64 with Rust 1.98.1 and Node v24.11.0. The macOS owner remains
alive through a canonical read that clears kernel-managed PENDIN before exact
attribute comparison. Other native platform checkpoints must repeat their native
cases; absent Python and Windows skips are never acceptance.

The prior [concurrent Node failures](c3.29-node-triage.md) remain unresolved stress
observations. Serial regression acceptance does not establish arbitrary concurrent
reliability. No runtime Rust change is introduced by this checkpoint; the release
binary is byte-identical to C3.29, whose Rust gates remain recorded separately.
