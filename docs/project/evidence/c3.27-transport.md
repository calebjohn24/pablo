# C3.27 increment — scoped task transport and cancellation receipts

C3.27 remains in progress. A standalone bounded A2A task transport is implemented and tested; supervisor/native-event integration, host/model delegation, separate remote usage and full R02 acceptance/merge remain pending.

`TaskClient` selects the validated HTTPS RPC endpoint, uses a pooled reqwest client with redirects/proxies/automatic retries disabled, and resolves no credentials itself. An optional host-supplied Bearer credential must match the exact endpoint/consumer and becomes a sensitive header. The explicit loopback fixture constructor cannot receive credentials. Preflight rejects unsupported selected input/output modes, unsupported streaming, expired time or prior cancellation before submission. Requests contain only selected Parts, output modes, zero history and optional trace context. Response correlation is validated only when the request actually negotiated the extension.

Each exchange uses the bounded lifecycle and raw SSE decoder. Raw chunks are charged before parsing; response bytes, progress idle, caller/wall time and sink delivery are bounded. Immediate Message, terminal Task and streamed Artifact/status shapes produce typed results with separate remote IDs and dispositions. Terminal updates end the response without waiting indefinitely for remote EOF. A wire-valid task/context ID is retained for cleanup even if the assembled-result wrapper exceeds its retained bound; rejected content does not enter accepted result state.

Cancellation/deadline/failure with a known nonterminal task joins one bounded CancelTask exchange. Its receipt is separate from the local outcome and reports a returned remote state, numeric rejection or unconfirmed cleanup. A canceled receipt is a peer assertion, not proof that remote work stopped or side effects were undone. Pre-cancelled requests remain `not_sent`; polling submission is conservatively `may_have_been_sent` until response headers arrive. Input/auth-required states remain distinct and trigger cleanup rather than automatic continuation or resubmission.

Expose host/model delegation with explicit Parts, preserve typed results within root retained-result limits, and label remote-reported usage separately from enforced local accounting.
