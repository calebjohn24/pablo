# C3.41 — Jev task complexity routing

Verified on 2026-09-17 on native macOS arm64, Rust 1.98.1 and installed Node 24.11.0. `.nvmrc` specifies 24.20.0; no toolchain was installed or changed. This feature does not claim the outstanding C3.36 Linux release acceptance.

## Result

Opt-in `options.routes.<name>.router` config selects `typesafe-ai/jev` through Vercel AI Gateway. Configurable instructions and 2–10 described categories map only to approved named Vercel text-model profiles. Schema validation, offline explanation/rendering, fingerprints, authority, exact endpoint credential scoping and doctor inspection include the classifier. Inspection reports no selected entry before task start. Existing routes retain their ordered fallback behavior.

The shared runtime evaluates original input and deployment instructions once before generation. The selected index belongs to the task, while provider resources remain immutable across reusable ACP sessions. Tool turns, compaction, repair and errors never change the selected profile. Invalid choices, malformed/oversized responses, provider rejection and timeouts stop the task; no classifier retry or model fallback occurs. Child narrowing cannot leave categories pointing outside inherited authority; classifier routes cannot be nested.

Classification has native model events and an `evaluate` span, participates in call/usage accounting and shared cancellation/deadlines, and never emits its choice as assistant text or adds it to generation history. Evaluation requests and responses are bounded to 128 KiB and 64 KiB. Evaluation usage is retained without applying text-generation token limits to a protocol that has no generation-token setting. Missing usage/cost remains unknown. Live hard accounting ceilings remain unsupported, consistent with existing gateway adapters.

## Findings and corrections

An initial credential-source attempt referenced the old alias, which the private loader rejected before network admission; the smoke now uses `AI_GATEWAY_API_KEY`. The first live evaluations exposed nonzero evaluation output-token accounting, which initially hit the text adapter's one-token placeholder. The runtime now separates evaluation from generated text limits; the fixture reports 73 evaluation output tokens to cover this difference. No credential, raw provider body or task trace is checked in.

Earlier combined test runs observed an existing ACP fallback notification-count assertion (3 versus 4), and one CLI spawn failed with ENOENT while Cargo was replacing the executable. A fresh run after builds finished passed all 90 tests. The notification assertion was not weakened or removed. The initial full Rust suite had 356 tests; the added credential/child regression raised the total to 357.
