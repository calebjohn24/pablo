# C3.34a filesystem search baseline and oracle

C3.34a is complete. It freezes current default literal-search behavior before the scanner changes and records an optimized native baseline for the proposal's later comparisons. No provider credential, paid call, live network dependency, temporary path or corpus content entered the checked-in evidence.

## Behavior oracle

`crates/pablo-core/tests/filesystem.rs` now contains an independent reference implementation built only from standard-library traversal and whole-file decoding. Production `fs.search` payloads are compared exactly against that oracle, including ordering, path spelling, line numbers, line text and N+1 truncation.

The deterministic fixtures cover a literal match crossing the current 8 KiB boundary, Unicode, LF/CRLF/no-final-LF, duplicate occurrences on one line, dense and sparse matches, no matches, hidden paths, nested traversal, invalid UTF-8 and NUL after an apparent match, and symlink exclusion. A separate limit fixture freezes huge nonmatching-line success, oversized matching-line output failure and invalid-tail rollback. Existing filesystem tests continue to cover policy intersections, unreadable admitted files, cancellation, path containment/races, tool-output limits and work limits.

## Measurement method

`npm run measure:search` builds the release binary and runs six deterministic corpora through the real ACP binary and actual `fs.search`. Every sample uses a fresh process and session, two local fixture-provider calls and one filesystem call. The provider verifies the exact tool payload before sending the terminal response. Five warmups precede 30 recorded warm-cache samples for each workload.

Prompt time spans the ACP prompt request through terminal delivery. Native tool time uses negotiated `pablo/v2` tool timestamps. Process CPU comes from `ps` around the prompt and has 10 ms resolution on this host. A separate validated run samples RSS and descriptor count approximately every 20 ms so polling does not contaminate timed samples. Traversal counts come from the generated fixture and reflect the current exhaustive walk; scanner-retained bytes are conservatively represented by the largest candidate because the current implementation reads each candidate completely.

The first full attempt tried to reuse one ACP process across the entire matrix and the connection closed after the supported task/session window. The final harness intentionally uses one fresh process per sample, which respects that bound and also makes incremental RSS comparisons independent of allocator retention. That failed attempt is not included in the baseline.

## Frozen baseline

| Workload | Content | Entries | Tool p50 / p95 | Prompt p50 / p95 | CPU p50 | Incremental peak RSS | Result bytes |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 512 small files, late match | 1,048,583 B | 512 | 12.216 / 15.253 ms | 15.579 / 18.713 ms | 20 ms | 6,704 KiB | 294 B |
| 256 MiB short lines, no match | 268,435,456 B | 1 | 500.768 / 613.523 ms | 504.348 / 617.239 ms | 510 ms | 270,640 KiB | 229 B |
| 32 MiB one line, no match | 33,554,432 B | 1 | 10.560 / 31.807 ms | 13.852 / 35.681 ms | 20 ms | 41,184 KiB | 221 B |
| 100 matching lines, one file | 3,390 B | 1 | 0.168 / 0.201 ms | 3.461 / 3.693 ms | 10 ms | 6,896 KiB | 9,004 B |
| 12.5 MiB selective tree, late match | 13,107,200 B | 102 | 18.126 / 19.810 ms | 21.374 / 23.285 ms | 20 ms | 6,736 KiB | 305 B |
| 40 deep + 256 wide, late match | 2,328 B | 297 | 15.533 / 16.671 ms | 18.793 / 20.123 ms | 20 ms | 6,736 KiB | 373 B |

The 256 MiB case confirms the motivating retention problem: 270,640 KiB incremental peak RSS while scanning one 256 MiB candidate. The dense fixture establishes a 9,004-byte default payload for a future path-only result comparison. The selective fixture visits 13,107,200 content bytes; a `src/**` include would visit 1,310,720 bytes, a 90% scope reduction.

The proposal's review targets are now frozen as follows:

- C3.34b: at least 80% lower incremental peak RSS on the 256 MiB corpus, or at most 54,128 KiB, plus a deterministic huge-line memory bound.
- C3.34c: at most 1,310,720 selected content bytes and at least 25% lower native p50 on the selective workload, or at most 13.595 ms. Scope reduction and engine speed remain distinct claims.
- C3.34d: at least 80% fewer serialized bytes in path-only mode on the dense fixture, or at most 1,800 bytes, while returning the same relevant path set.
- Any default-workload p50 or p95 increase exceeding both 10% and 0.5 ms triggers investigation and an alternating matched rerun; it is not an automatic CI ceiling.

The sanitized aggregate report is [c3.34a-search-baseline.json](c3.34a-search-baseline.json). Raw per-sample data stays under ignored `.pablo/measurements/`.

## Handoff

C3.34b can replace whole-file retention with a bounded streaming literal scanner. It must preserve the oracle payloads and failure precedence, then compare the saved source/executable/harness identities and frozen workloads using matched native hosts. Release packaging C3.34 remains separately blocked by the standing user hold.
