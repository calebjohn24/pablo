# C3.12 — Fallback failure and accounting proof

F03 exposes every routed model start/finish as a bounded `model-route-v1` record,
with route entry/order, logical operation/attempt, initial/sticky/fallback selection,
phase, dispatch/delivery, safe failure/limit/class and cumulative exact accounting.
The runtime retains only the latest selection. CLI JSONL contains the complete
sequence; terminal metadata includes an entry blocked before dispatch. The closed
`c2.3` task envelope and deployment configuration revision `c3.11` are unchanged.

ACP peers explicitly negotiate `pablo/model-route-v1` plus `pablo/v1` to receive
`_pablo/model_attempt`. Notifications use the existing bounded queue and physical
write acknowledgement. No tool or thought update is invented. Generic and older
extended peers receive their existing shapes. The extension schema validates both
attempt correlation and terminal records. Credential failures precede CLI run
admission and ACP initialization and therefore have no fabricated attempt events.

A received provider event now prevents a subsequent transport error from claiming
NotSent. Its unknown reservation remains charged and uncertain-delivery retry still
requires opt-in; reported actual cost can settle independently of unknown tokens.
This closes a core accounting/policy gap without changing provider error text or
exposing bodies, credentials or private continuation. GLM defaults and unlimited
filesystem-work defaults remain unchanged. No live provider requests were made.
