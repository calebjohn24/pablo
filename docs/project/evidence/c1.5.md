# C1.5 — Collector proof

## Implementation

CLI `run`/`demo` and ACP now share a standalone SDK with opt-in OTLP/HTTP Protobuf export. The core retains its injected tracer and original lifecycle instrumentation; `Runtime::with_parent_context` adds explicit parenting without global context. CLI flags and negotiated ACP `pablo/v1` prompt metadata extract bounded W3C traceparent/tracestate; baggage is ignored. Native run records include the remote parent ID.

The pinned OTLP/HTTP exporter, HTTP/proto crates and SDK batch processor use an owned current-thread executor on the batch thread. The HTTP adapter bounds response bodies, prevents redirects, retains credentials outside runtime contracts, and reports sanitized partial rejection/failure counts. Shutdown cancels HTTP/retry futures at 1.9 seconds so the SDK worker can join within the two-second deadline. Export settings and unsupported capabilities are documented in [telemetry](../../telemetry.md); D017 records the ownership decision.

## Real Collector acceptance

`npm run smoke:collector` passed on macOS arm64 with Node 24.20.0 and Rust 1.98.1. It downloaded the official **otelcol 0.160.0** archive, checked its SHA-256 against [the committed lock](../../../tests/fixtures/collector/lock.json), and ran [the pinned configuration](../../../tests/fixtures/collector/config.yaml) on loopback. The Collector decoded real HTTP Protobuf and forwarded OTLP JSON to the fixture assertion server.

The final invocation reported **4 spans and 10 native events**, with all assertions passing:

- One run span under the incoming remote W3C parent, two model spans and one shell span under that run; remote-parent flags and tracestate preserved.
- All trace/span/parent identities and exact start/end timestamps match native JSONL, including the external parent on root records.
- Resource service-name precedence, executable version, instrumentation scope and pinned GenAI schema are correct.
- A real shell result feeds the second local model response; native and ACP terminal outcomes are completed.
- Task input/output, shell command/output, synthetic credentials and baggage are absent from Collector payloads. Credentials are absent from ACP stdout, diagnostics, native content-enabled traces and provider request bodies; shell environment excludes credentials and context.
- Pablo exits with code 0 and no signal; Collector exits cleanly after SIGTERM; the temporary workspace is removed. No client-enforced kill is needed.

The final fixture's runtime observation was 38 ms (an earlier successful invocation was 798 ms). These are uncalibrated observations, not performance baselines. The model is a local HTTP/SSE fixture; no live provider credential was loaded and no paid request was made. Downloaded archives/executables remain ignored under `.cache/collector/`; raw native and Collector payloads are temporary and not committed.

## Findings corrected during implementation

Initial checks were not all green. The first real Collector attempt proved span topology/identity/timing but caught the pinned SDK's resource detector order overriding `OTEL_SERVICE_NAME` with `OTEL_RESOURCE_ATTRIBUTES`. The initial redirect fixture exposed its retry classifier treating redirects as retryable; source review also found it retries every 5xx. The adapter now applies standard service-name precedence and limits HTTP retries to OTLP's 429/502/503/504 list, honors Retry-After on 429/503, and keeps response bodies private. Subsequent real and offline checks passed.

An initial TypeScript check rejected a fixture callback returning `ServerResponse` instead of void; the callback was corrected. The first Rust regression run reached an existing help test still expecting C1.3; its checkpoint assertion was updated to C1.5 and all Rust tests then passed. No unresolved C1.5 acceptance failure remains.
