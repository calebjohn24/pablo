# C3.31 — D01 offline doctor and focused diagnostics

The [doctor contract](../contracts/c3-doctor.md) specifies the offline report,
explicit probes, private credential handling and stable diagnostic exit codes.
Doctor uses the ordinary deployment/bootstrap/override rules and private scoped
credential resolvers. It performs no agent execution and constructs no telemetry
SDK/exporter. The provider probe reuses the existing transport and request encoders;
MCP probing uses ordinary configured startup followed by explicit joined close.

## Behavioral acceptance

Focused cases verify legacy missing/present/unusable credentials, environment/.env
precedence, configured credentials and secret files, pinned protocols, source and
provenance metadata, active child configuration, and omission of private MCP
arguments. A configured offline fixture points provider and OTel at a counting
HTTP peer and installs a marker-writing MCP command: it requires zero requests,
no MCP launch and no trace creation.

Explicit provider probes cover HTTP acceptance, authentication/access rejection,
model-request rejection, server failure and redirect refusal. They send one small
request with no tools and do not expose response bodies. A configured route must
probe only its first entry without fallback; Open Responses uses its own configured
encoder and output allowance. These tests use synthetic local peers, never real
provider credentials or services.

MCP tests cover required failure, optional omission and successful negotiation with
the pinned independent SDK. The successful fixture records its real process ID;
after doctor returns, its process group must be gone and no tool-call marker may
exist. Static executable policy denies launch before a marker is written. Ordinary
CLI setup/provider failures include doctor cause/fix hints and retain their existing
exit codes. The plain report remains readable and free of executable controls.

## Development findings

The first credential-file fixture used unsupported `raw` encoding; it now uses the
schema's `utf8` value. An initial policy fixture used the MCP dimension name
`launchers` under the ordinary policy; stricter error classification correctly
reported invalid configuration, exposing that fixture mistake. The valid ordinary
policy dimension is `executables`; the final case proves actual policy denial.
These corrections did not relax assertions or deadlines. Clippy also caught a
nested formatting call in help text, corrected before final verification.

Provider success intentionally reports HTTP/SSE request acceptance, not generated
output validation. A gateway can reject a model request for multiple reasons, so
the diagnostic does not claim a raw remote error message proves a specific cause.
Credentials and raw remote content are never copied into project records.

## Pre-merge cancellation review

LOG-0155 records the initial passing gates (344 Rust, 332 serial Node and sixteen
focused doctor cases). Source review then found no Ctrl-C handler for an explicit
MCP probe. Normal return/timeout cleanup had passed, but interruption was not
proved. C3.31 was reopened before commit or merge (LOG-0156).

Doctor now propagates a real cancellation token and awaits in-flight diagnosis,
including MCP startup's owned cleanup, before reporting interruption. A real
SIGINT fixture observes the spawned shell, interrupts doctor, requires exit 130
and proves the owned process group is gone. The fixture validates PID input before
any process-group cleanup. Provider interruption drops the owned request without
claiming remote generation stopped. An actual cleanup failure retains its failure
code rather than being relabeled successful cancellation.
