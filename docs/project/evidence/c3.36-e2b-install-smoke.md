The installed binary reported `pablo 0.0.1` and the exact expected SHA-256. `pablo demo` returned `Hello from pablo.` with no Node, Python, source checkout, provider credential or network access. A real 100-by-30 E2B PTY ran the demo and returned both expected markers.

The installer refused `--update` to the already installed `v0.0.1`. Receipt-verified removal deleted the binary and receipt while preserving an unrelated prefix file. The sandbox was killed, and a follow-up E2B listing found no running sandboxes.

Three earlier fresh sandboxes were also killed after the temporary harness exposed expected-doctor-exit handling and two current E2B SDK PTY API details. The final sandbox completed every Pablo check. Its only post-check harness error was an optional E2B metrics query with an invalid time range; this occurred after verified removal and does not change any Pablo result. Metrics are not used as acceptance evidence.
