# C3.3 progress: optional filesystem work quotas

The user reported `pablo: run limit exceeded: FilesystemWork` and explicitly requested removal of that default limit. D038 removes all four implicit work quotas: file bytes, visited directory entries, traversal depth and scanned bytes. Rust uses `Option<usize>` with `None` defaults; deployment fields use `"unlimited"`. Explicit positive host ceilings remain enforced. The core, legacy CLI/ACP and configured CLI/ACP share these defaults. No live provider or real credential was used.

Sorted depth-first search now uses explicit iterator frames instead of recursive calls. Removed the extra fixed 4,096-byte child-path work-limit failure; actual unsupported paths still produce filesystem errors. Cancellation, deadlines, no-follow workspace policy, UTF-8 validation, output bounds, paginated reads/listings and revision-checked atomic mutations remain. Snapshot/entry retention scales with actual work when no host quota is supplied.

This deliberately updates the deployment schema/defaults, production effective fingerprint, defaults source digest and derived input fingerprint. All file/profile source hashes and provenance remain intact. C2 numerical defaults remain historical in prior evidence; the current contract and option inventory point to the correction. `docs/context.md` and its reviewed hash are unchanged.

## Matched performance

[Measurements](c3.3-filesystem-unlimited-measurements.json) preserve four sequential runs of 30 samples plus five warmups per workload on macOS arm64. Tool p50 milliseconds:

| Workload | C3.2 baseline | Current | Current repeat | Baseline repeat |
| --- | ---: | ---: | ---: | ---: |
| read_128k | 0.188 | 0.177 | 0.172 | 0.174 |
| list_1000 | 1.438 | 1.464 | 1.325 | 1.203 |
| search_1m | 2.575 | 2.872 | 2.454 | 2.574 |
| replace_128k | 0.605 | 0.650 | 0.574 | 0.618 |
| edit_128k | 0.527 | 0.517 | 0.510 | 0.513 |

The first search pair increased by 0.297 ms; the reverse-order repeat decreased by 0.120 ms. Listing varied between 1.203 and 1.464 ms across runs. These short local runs do not establish a persistent performance regression or a general speedup. No benchmark overlapped compilation or tests. Complete configured lifecycle/resource-reuse measurements remain required by C3.3.
