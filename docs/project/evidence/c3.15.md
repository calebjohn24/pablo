# C3.15 — MCP configuration and policy contracts

M01 adds offline host admission for the tool-only MCP subset. The
[frozen contract](../contracts/c3-mcp.md) records the audited SDK, protocol and
telemetry revisions and the transport bounds that M02–M04 must implement.

## Implemented behavior

- Deployment revision `c3.15` accepts closed named stdio/HTTPS definitions,
  required/optional admission, bounded launch arguments, cwd, timeouts, environment
  and header credential references. Configuration inspection performs no server
  startup or secret read. Consumer and credential-authority checks include MCP.
- Server definitions replace as a unit; stale arguments and credential bindings
  cannot survive composition. Normalized defaults receive default provenance while
  declarations retain their source history. Render/reload preserves identity.
- Exact server, qualified tool and launcher policies intersect immutable MCP
  ceilings, existing tool/executable policies and host tool-name ceilings. Deny
  rules precede allow rules. An allow rule cannot add an unconfigured server.
- Canonical server/tool identities map bijectively to bounded provider aliases;
  duplicate identities, reserved aliases, invalid names and catalog overflow reject.
- The official ACP wire types normalize into exact host-definition selection.
  Unknown/duplicate servers, changed commands/arguments/URLs, client credentials
  and unsupported transports reject before use. Initialization advertises no MCP
  transport capability. Configurations awaiting transport implementation can
  initialize for admission diagnostics without resolving provider credentials.
- Required denied servers fail admission; optional denied servers are omitted.
  An admitted transport still reports its owning implementation checkpoint before
  any model, credential or server I/O. Actual startup failure and cleanup behavior
  remain M02/M03/M04 acceptance, not claims made by these offline checks.

The exact `rmcp=3.3.0` dependency is dev-only at this gate. Its release source
negotiates `2025-11-25`; moving upstream documentation is not the version authority.
The SDK's default async line reader is unbounded, so the frozen contract requires
bounded framing while retaining its protocol machinery. Actual MCP credential
resolution must bind consumer, server, destination and binding name at M02/M03.

## Verification and measurements

- `cargo test --workspace --locked`: 215 passed, including server replacement
  and mandatory host-policy derivation regressions.
- `node --test tests/*.test.ts`: 250 passed; the final 12-test deployment rerun passed after the API tightening; `npm test`: 34 passed.
  The MCP ACP test checks both transports, altered definitions, private input
  rejection, capability advertisement and absence of filesystem effects.
- TypeScript, warnings-denied Clippy, formatting, debug/release executable and
  measurement-host builds, and the offline schema/golden audit passed.
- The first full run exposed the expected outdated golden fixture and ACP's early
  startup rejection. Both were corrected and verified. One fallback notification
  count failed transiently in the first interface run; the focused 30-test rerun
  and full 250-test rerun passed without a fallback-code change. This does not
  isolate its timing cause; retain the observation for compatibility follow-up.
- All gateway tests used local synthetic fixtures. No live provider check or root
  credential-file inspection occurred.

The initial matched configured comparison is retained alongside final measurements.
Review removed a redundant ACP startup resolution and made tool admission derive
its policy exclusively from the resolved deployment. The final release is rebuilt
and remeasured after both changes. No tests or builds overlap measurements.

## Matched performance

[Five retained reports](c3.15-measurements.json) use 30 samples and five warm-ups.
C3.14's saved release is the baseline. The preliminary configured report precedes
final review changes; the final configured and filesystem reports match source
`ef6ef6a320118e40138756c14f48426eecd2168402b58f6dda21bdc02a2cd131`.
No transport workload is claimed before its implementation gate.

Final baseline/current p50 (ms): core 8.871/9.122; ACP initialization 9.598/10.252;
fresh prompt 15.720/16.407; warm prompt 14.410/15.024. Warm prompt p95 is
15.961/15.943. These observations include admission and host effects and do not
isolate MCP overhead. The preliminary warm median was 13.902 ms; retain both
observations rather than selecting the faster report. C3.39 retains the existing
schema-tail investigation and these configured startup/median observations.

Filesystem prompt medians baseline/current (ms): read 1.490/1.547,
list 2.120/2.136, search 3.042/2.966, replace 2.203/2.255, edit 1.289/1.269.
Release size is 11,697,824 versus 11,581,680 bytes (+116,144; 1.00%).
