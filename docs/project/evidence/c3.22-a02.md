# C3.22 — One supervised local child (A02)

C3.22 enables one depth-one temporary child through configured CLI and ACP roots.
The model-facing subagent actions and direct host operations share one supervisor,
root ledger, existing runtime and typed ACP handlers. Children are disabled unless
`options.children.enabled=true`. One manager awaits each FIFO child execution;
two active children remain C3.23.

The final test additions did not require runtime changes. Initial assertions were
corrected to the established protocol contracts: timed-out ACP prompts return an
error carrying the timed-out task; child startup failure is `child_admission`;
configured pre-run CLI errors exit 2 on stderr without a task envelope. These were
test expectation errors, not silently relaxed outcome checks. The final seven
public child cases all pass without skips.

Final verification: workspace Rust 302 passed with 11 ignored; explicit factory
and child-admission suites passed three and seven, yielding 305 distinct passing
Rust tests. All 272 Node tests, 34 project tests, TypeScript, warnings-denied
all-target Clippy, formatting/diff and debug/release binary/example builds passed.
Eight pre-existing ignored MCP acceptance/performance cases were not rerun in this
checkpoint and are not claimed as passed here; their earlier cycle evidence remains
historical. This checkpoint used synthetic local providers and the installed
isolated MCP fixture. No live provider credentials were read.

C3.22's listed acceptance is complete. C3.23 next enables two concurrent children
and proves A03 overlap/isolation with shared-budget races. Full extensibility matrix
acceptance remains C3.25; prior F03 remains C3.33, and cross-platform/release-level
performance remains C3.35–39. Those future gates are not claimed by A02.

## Final performance

[Matched existing-workload measurements](c3.22-a02-measurements.json) and
[same-binary child workloads](c3.22-a02-children-measurements.json) ran sequentially
after all tests/builds with 30 samples and five warm-ups. Saved baseline/current
medians (ms): core 8.898/9.262; ACP initialize 10.664/10.465; fresh prompt
15.926/16.256; warm prompt 14.993/14.426. RSS was 18,160/18,656 KiB; release size
13,795,856/14,377,792 bytes. Filesystem tool medians read/list/search/replace/edit
were 0.135/0.134, 0.982/1.118, 2.063/2.061, 0.523/0.497 and 0.432/0.418 ms.
Results remain mixed, with higher core/fresh/list latency, RSS and size visible for
C3.39. Measurements establish observed behavior, not causal improvements.

On the same final binary, disabled/one-child complete CLI medians were 8.475/9.805 ms;
fresh ACP was 10.060/12.233 ms. The enabled workload includes four aggregate model
calls and two subagent tools, versus one model call with children disabled. Every
iteration asserts exact accounting and successful outcomes. This comparison includes
extra useful work, not isolated scheduling cost. It uses local fixtures and no
trace; live-provider and two-child timing remain separate work.
