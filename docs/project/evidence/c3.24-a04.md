# C3.24 — Validated child handoffs (A04)

A parent explicitly selects owned `{source_agent_id, result_id, kind}` entries on
spawn. Successful settlement assigns a stable result UUID; only matching, completed,
schema-valid results resolve. The supervisor adds selected structured output and
validation/repair, accounting and native trace receipts to ordinary child context.
Downstream snapshots retain selections; source snapshots remain owned through root
shutdown. No source transcript, capability or trusted instruction transfers.

Artifact output is an exact workspace-relative `{path, revision}` reference. After
queue promotion, before child setup, verification applies the narrowed `fs.read`
capability and read-root policy, existing physical no-follow regular-file access,
and streaming full-file SHA-256. Existing explicit file-byte limits and deadlines
apply; cancellation joins the verifier. Defaults remain unlimited for filesystem
work. This verifies the revision at admission; later concurrent writes can change
content. No artifact store, scheduler, retry or persistence was added.
