# C3.22 partial — Scoped process and child MCP capacity

Scoped shell execution reserves one process slot from the root ledger before
ordinary tool admission and dispatch. Capacity failure emits the existing native
admission failure without spawning a shell or charging a tool call. The permit
remains owned across the tool future and its joined cleanup. It is released before
the enclosing run settles. Unscoped execution preserves its existing behavior.

PreparedRun computes conservative MCP capacity from selected servers after the
same server-policy intersection used by its capability factory. Each admitted
server reserves a session; stdio additionally reserves a process. This calculation
starts no capabilities or credential resolution. The supervisor atomically promotes
queued children with MCP, process, context and result capacity in the existing
lease. Direct child dispatch reserves the same MCP/context capacity at admission.
Binding rejects a lease that belongs elsewhere or does not cover the prepared
requirements. Optional servers keep their reservation until task cleanup joins,
even when they are omitted after startup failure. This deliberately avoids early
release while any owned startup or teardown work could remain.

These changes reuse the dispatcher/worker lease ownership already established in
C3.22. A cancelled close caller retains the owned shutdown task; the dispatcher
releases capacity only after acknowledging its worker join. The production shell
test observes the process slot at ShellStarted, cancels, then verifies the process
group is gone and the slot released at RunFinished. The exhausted case admits no
ShellStarted event and spends no tool allowance. The held-worker test now checks
MCP/process capacity as well as the active slot, rejects an underfunded binding,
and verifies complete release after the join. Child-admission fixtures check HTTP
versus stdio requirements and empty/narrowed selection.

The first workspace run exposed an existing cancellation/delivery race in the
invalid-root-preflight test: 16 binary tests passed and one observed EventSinkIo
instead of Cancelled. A closing ACP queue can fail delivery after cancellation is
already requested. Lifecycle now classifies that I/O failure from its cancellation
signal and shared deadline before native model/run settlement. An explicit test
cancels inside a text sink, returns I/O failure and checks the native terminal and
returned outcome agree on cancellation. Cleanup failures retain their existing
priority. A subsequent all-target compile caught a test-only token name typo in
the compaction fixture; it was corrected before final verification.

Final verification: full workspace Rust suite 278 passed, nine ignored; explicit
child_admission run seven passed, including one otherwise ignored test (279 distinct
Rust tests verified; eight pre-existing ignored cases unrun). Rebuilt Node suite
265 passed; project tests 34 passed. TypeScript, all-target warnings-denied Clippy,
formatting/diff checks and debug/release binary/example builds passed.
