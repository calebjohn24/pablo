# C3.23 — Two children and shared budgets (A03)

The manager polls a bounded set of two owned child executions. Pending jobs enter
that set FIFO when capacity becomes available. On cancellation, deadline or lost
updates it closes admission, settles queued work, then drains every active future
through native delivery and joined worker cleanup before closing root updates.
Root MCP/tool cleanup remains outside that completed drain. The ledger admits up
to the existing MAX_ACTIVE=2 ceiling, retaining the one-slot-per-child invariant.

| Process/MCP admission | Separate final-process and final-MCP races admit one child without partial capacity changes. Existing root factory and child capability tests still hold permits before external setup through joined cleanup. |
| Aggregate events/trace | A three-agent trace race leaves exactly one ordinary event after protecting all three terminal reservations. Only one contender succeeds; all terminals can settle after admission closes without overspend or double charge. Root-sequence ordering remains contiguous in configured trees. |
| Narrowed authority and limits | Existing child contract/admission/typed-dispatch tests rerun unchanged for route/provider credentials, native tool policy, Skills, MCP catalog/selection, root identity and inherited limits. The concurrent manager uses those same admission paths; it introduces no alternate authority source. |

Old one-slot tests were updated by occupying the other slot before racing for the
last allowance, or by explicitly observing both provider requests. This preserves
the original ownership and all-or-nothing assertions. Child calls remain sequential
within an agent; this change overlaps two owned child loops only. Handles/results
remain outside compaction history.
