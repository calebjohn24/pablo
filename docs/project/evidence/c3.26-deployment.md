# C3.26 increment: deployment selection and scoped RPC credentials

C3.26 remains in progress; this evidence does not claim full R01 or remote execution.

Host configuration now accepts up to sixteen named HTTPS card/RPC definitions, optional bearer scheme/credential references, and explicit trace opt-in. Every `authority[].a2a_remotes` layer restricts exact named URL pairs; credential references also intersect ordinary credential-ID ceilings. Offline resolution validates definitions and credential consumers without accessing secrets. `PreparedRun::a2a_credential` selects only configured names and scopes bytes to the exact RPC endpoint and separate `a2a.bearer` consumer. Public card retrieval never uses those bytes. Named offline card admission validates against the configured definition.

Contract revision c3.26 updates both schemas, defaults, normalized provenance, render/reload fingerprints and the independently audited production golden. Missing trace opt-in canonicalizes to false; defaults have no remotes. D056 explains why card metadata is not local authority. See [the contract](../contracts/c3-a2a.md).
