The default release profile strips debug information. The smaller figures are separately stripped copies; timing uses the actual release executable, and neither copy is published. The artifacts exceed the brief's provisional 10 MiB headless target, while the stripped copies are below its provisional 15 MiB default-distribution target. These comparisons inform later work; C1 establishes the baseline rather than retroactively imposing those targets.

The core/ACP workload uses identical CLI-derived instructions/spec, two loopback HTTP/SSE calls, one real shell and 32 × 16-byte output deltas. Core run timing excludes provider/tool/SDK construction; ACP prompt timing includes per-prompt setup and final delivery. Its ratio therefore includes more than stdio encoding. Differences in platform scheduling, shell startup, filesystem and virtualization prevent treating this table as a native macOS-versus-native-Linux speed ranking.

The event benchmark excludes network/SSE parsing and includes fixture clock/mutex overhead. The JSONL percentage is intentionally reported even though it is much larger than the brief's provisional 2% writer-share target: this workload spends no time waiting for a model and writes a repeated correlation envelope for each event. The absolute overhead is roughly 1.2–1.4 ms per 1,000 deltas. Measure real workloads before promoting writer optimizations or a regression gate; C1 does not claim the 2% target is met.

Both measurement reports match source SHA-256 **`20117cd9962a1f9a695056b78a55d44a0518fb1c560a6daeaf4c28cd5b50c246`**. The fingerprint covers executable/fixture/measurement sources, manifests, lockfiles and toolchain pins; changing handoff records does not alter it. Individual sample timings remain ignored in `.pablo/measurements/c1.6-darwin-arm64.json` and `.pablo/measurements/c1.6-linux-arm64.json`.

## Limits and handoff

This checkpoint satisfies the cycle's macOS/Linux focused-fixture gate on arm64. It does **not** establish native Linux x86_64 measurements from the broader release brief, a release target matrix, cold-cache or remote TLS timings, warm/reused ACP sessions, eight-agent performance, or a complete alpha.1/0.1 product. Live Vercel is proved on macOS; Linux proves the deterministic transport path and real Collector, with no copied provider credential. Custom OTel TLS configuration and other explicitly unsupported C1.5 capabilities remain documented limits.

The next step is to review/adopt [proposed C2: single-agent completion](../proposals/002-single-agent-completion.md), covering bounded filesystem tools, a machine-readable task surface and selected policy/accounting gaps before broader extensibility. Initialize its cycle state in a new session; no C2 checkpoint is active yet. Keep native Linux x86_64 validation and comparable measurement repetitions in the next acceptance plan. No publishing or durable-session work was started.
