# C3.16 — MCP stdio tool path

M02 enables one fresh, host-admitted MCP catalog through the async Rust embedding
API. The ordinary runtime consumes the independent server's actual synthetic read
result. CLI/ACP transport integration and Collector acceptance remain C3.18;
Streamable HTTP remains C3.17. This gate makes no live-provider or CLI MCP claim.

## Implementation and acceptance

- Official Rust SDK `rmcp=3.3.0`, release commit
  `3e636cab26c013eca5131103c03d20237f12c4df`, negotiates only `2025-11-25`.
  A bounded transport replaces its unbounded reader without replacing protocol
  correlation. Direct typed discovery/call requests avoid catalog caching and
  automatic multi-round tool invocation or replay.
- `PreparedRun::tools_with_mcp` derives immutable host policy, contained cwd and
  scoped credentials before launch. Environment is cleared; only declared private
  bindings enter the server. Server, launcher and qualified tool policy intersect
  existing authority. Discovery cannot grant an unapproved tool.
- Discovery bounds frames, schemas, pages, tools, descriptions and total catalog
  bytes. Arguments validate before dispatch. Text and structured object results
  retain `isError`; declared success output validates locally. Error results may
  omit success output, but supplied structured content still validates. Protocol,
  tool, validation and unsupported-content failures remain distinct typed outcomes.
- A per-server mutex and single-use registry bound pending work and prevent reuse
  across runs. Startup shares the root deadline. Required startup failure closes
  all previous servers; optional failure records a fixed omission reason. Cleanup
  failure is fatal even for optional servers.
- Cancellation interrupts bounded transport I/O, attempts a bounded notification,
  then kills the owned process group and joins the SDK, child and stderr reader.
  Terminal delivery follows cleanup. Stderr is drained with a fixed buffer and
  saturated byte counter; raw text is discarded. Dropping a future/catalog is only
  a fallback: embedding hosts must drive cancellation or explicit close to completion.
- Canonical identities map to 52-character provider aliases with collision checks
  and a per-request reverse map. Tests cover maximum-length identities, fragmented
  Vercel/OpenRouter names, and Open Responses continuation through `[DONE]`.
- MCP attributes decorate the existing CLIENT tool span. Independent fixture
  metadata proves the propagated traceparent and request ID match that span.
  Metadata-only native traces omit actual result content and credentials. MCP calls
  do not emit shell lifecycle events or duplicate logical tool spans.

## Verification

- `cargo test --workspace --locked`: 219 passed; five opt-in MCP tests are explicitly
  separate from this count.
- `cargo test --locked -p pablo-core --lib mcp:: -- --ignored`: 3 passed, covering
  the actual Python SDK read, invalid arguments without dispatch, cancellation and
  17 hostile peer modes. Cases include hanging startup/call, wrong protocol,
  missing tools, oversized frames/catalog, duplicate names, unsupported schemas,
  repeated cursors, protocol errors, unsupported results, invalid output, bounded
  progress, stderr flooding, descendant cleanup and tool errors.
- `cargo test --locked -p pablo-core --test mcp_stdio -- --ignored`: 2 passed,
  proving private host credential use, actual result consumption, cleanup before
  terminal emission, single-use rejection, native/OTel context correlation,
  required failure cleanup and optional omission. The independent fixture pins
  Python SDK `mcp==2.2.0`; distribution hash and dependencies are recorded in
  [the fixture](../../../tests/fixtures/mcp/README.md).
- `node --test tests/*.test.ts`: 250 passed. Final rebuilt ACP rerun: 67 passed.
  `npm test`: 34 passed. TypeScript, warnings-denied Clippy, formatting,
  debug/release executable and measurement builds, and schema/golden audit passed.
- Initial fixture failures exposed Python SDK v2 import/meta API differences and
  a test missing the Open Responses terminal marker; corrected fixtures pass.
  A broader CLI cancellation test raced an empty PID file. Its shell fixture now
  publishes the PID atomically; the full suite passes after that correction.
- All provider traffic was synthetic/local. The root credential file was neither
  inspected nor used. No skipped live, ACP MCP or Collector gate is marked passed.

## Performance

[Five retained reports](c3.16-measurements.json) use sequential 30-sample runs with
five warm-ups and no test/build overlap. The current measured source is
`d0b9f91b2fef1fed2f2a9f3322dec27408e6065d8195b1106dac64a518e34f80`.
The baseline is the saved C3.15 release, source
`ef6ef6a320118e40138756c14f48426eecd2168402b58f6dda21bdc02a2cd131`.

Baseline/current p50 ms: core 9.437/9.363, ACP initialization 11.144/10.413,
fresh prompt 16.588/16.370, warm prompt 14.887/14.660. Warm prompt p95 is
15.690/15.802; fresh p95 is 17.544/18.072. Filesystem prompt medians are mixed:
read 1.531/1.519, list 2.065/2.082, search 2.858/2.869, replacement 2.200/2.246,
edit 1.274/1.292. These local observations do not isolate overhead or establish
universal equivalence; existing C3.39 investigations remain open.

The new native MCP workload starts a fresh Python SDK process/catalog each run.
Startup median/p95 is 239.886/250.852 ms; actual tool median/p95 is 0.799/0.997 ms;
run including joined close is 2.245/4.389 ms. Tool time includes the fixture's
context-metadata write; configuration and fixture construction are excluded.
This measures Python startup plus local transport, not remote model latency.
Release executable size is 11,933,600 versus 11,697,824 bytes (+235,776; 2.02%).
