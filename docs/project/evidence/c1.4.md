# C1.4 — Live Vercel ACP acceptance

## Implementation and scope

Added `scripts/smoke-live-acp.ts` and `npm run smoke:live:acp`, using the existing official TypeScript client, actual Rust executable, shared runtime and direct Vercel HTTP/SSE adapter. No second model loop or transport was needed. The script is included in TypeScript checks but excluded from ordinary test commands. See [execution and credential rules](../../acp.md#live-acceptance).

The fixture forces private loading of the ignored root `.env` by the executable, removing inherited key and fixture-endpoint overrides. A random marker exists only in a temporary evidence file before execution. The harness requires one successful shell read, two model calls and the actual marker in the streamed/final answer. Fixture-only limits are one tool call, two model calls, a 90-second run and a 10-second shell deadline. D014–D016 remain the model/defaults authority.

Added offline ACP cases for HTTP rejection bodies, SSE errors, incomplete streams, usage aggregation, and missing/invalid credential files. Updated usage instructions and corrected a stale gateway documentation reference from a 15-second to the actual 60-second connection timeout; runtime defaults did not change.

The first completion-state check rejected LOG-0024 because its `problems` field contained scope notes. LOG-0025 records that failure, and LOG-0026 corrects the classification without rewriting history. The offline/live distinction and future gates remain explicit here and in the handoff; no C1.4 acceptance problem remains.

Each has `response_received` delivery certainty, one native failed outcome, no shell execution, no retries and no leaked response body. These are deterministic loopback observations, not induced live Vercel failures.
