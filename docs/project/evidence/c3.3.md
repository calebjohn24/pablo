# C3.3: configured runtime and deployment inspection

C3.3 passes all nine G03 cases on macOS arm64 through the shared C2 runtime. Configuration can be validated, explained and rendered offline; configured CLI, ACP and Rust hosts project equivalent admitted options and identities. Live provider, future subsystem, native release and distribution gates remain assigned to later checkpoints. This evidence completes the earlier partial [inspection work](c3.3-progress.md) and [filesystem correction](c3.3-filesystem-unlimited.md).

## Implementation and fixes

- The bounded resolver captures explicit file/profile/environment/host inputs and preserves sources, overridden origins and canonical effective/input fingerprints. Rendered TOML reloads with the same effective identity and credential references.
- Shared `PreparedRun` projects the immutable spec, policy layers, actual workspace/trace paths and private binding identity. CLI and ACP validate credentials, provider capabilities, trace capacity and explicit exporter settings before running. Trace creation is exclusive, private and no-follow through every parent.
- Every ACP task re-resolves inputs. Active tasks keep their admitted policy/resources; subsequent admissions observe file edits, actual binding changes and private credential rotation. Resources are reused only while config, bindings and privately compared credentials match. Changed exporters are shut down and joined before replacement.
- Independently evaluated authority policies intersect their allowlists and retain deciding rule IDs. CLI `--policy` now replaces ordinary omitted dimensions with explicit allow defaults instead of serializing invalid null values or retaining obsolete ordinary restrictions. Authority rules remain intact. Configured policy-file errors use safe config diagnostics.
- Configured SDK and OTLP builders bypass ambient detectors and header merging through three narrow behavioral patches to exact pinned sources. Vendor hashes, original versions and Apache licenses are recorded. No process-global environment mutation is used. Legacy constructors retain prior behavior. D039 explains this ownership choice.
- Scoped credentials use absence-only fallback, bounded no-follow file reads, literal dotenv parsing and strict private destination checks. Invalid unrelated control bytes in dotenv now reject; selected secrets never enter inspection or runtime identities. The fixture adapter never reads or forwards the real-provider reference.
- Safe deployment identity appears on native start/finish, ACP metadata and the root span. Full config, source contents, physical bindings and credentials remain outside runtime telemetry. An ACP startup preflight now uses a fresh temporary identity rather than colliding with an unrelated `startup.jsonl` file.
- D038's user-requested unlimited filesystem work defaults remain in all interfaces. Explicit host quotas, cancellation, output bounds and revision-checked mutation still work.

## Performance

[Aggregate measurements](c3.3-measurements.json) retain source/build/harness identity, platform/tool versions, timing boundaries and p50/p95/p99 distributions; raw local timing samples remain ignored. Each column has 30 samples after five warmups; no compilation or tests overlap measurements.

| Metric | C3.2 baseline | C3.3 legacy | C3.3 configured |
| --- | ---: | ---: | ---: |
| CLI total ms | 15.756 | 14.657 | 17.872 |
| Core run ms | 8.722 | 8.331 | 8.465 |
| First ACP prompt ms | 10.899 | 10.348 | 9.445 |
| Warm ACP prompt ms | 8.052 | 7.926 | 8.458 |
| First-delta delivery ms | 0.287 | 0.268 | 0.290 |
| Idle RSS KiB | 8160.000 | 8304.000 | 15040.000 |
| Warm idle RSS KiB | 13872.000 | 14320.000 | 16304.000 |

The binary grows from 10,464,688 to 11,115,104 bytes (650,416 bytes). Legacy medians remain close to baseline, with noisy tails rather than a claimed general speedup. Configured CLI adds 3.215 ms relative to current legacy; a reused ACP task adds 0.532 ms. Configured initialization includes admission/schema/client validation before the idle RSS observation, unlike legacy lazy setup; warm RSS differs by about 1.94 MiB. The first ACP prompt is faster in the configured sample because some setup already happened at startup, so compare startup and prompt boundaries together.

Filesystem tool p50s remain sub-millisecond for 128 KiB reads/mutations and roughly 1.3–2.8 ms for listing/search. Configured prompt timing includes fresh config resolution and admission; the actual filesystem worker is the shared implementation. These local samples describe cost without inventing a performance ceiling or proving other architectures. The final release performance gate remains C3.39.
