# C3.25 — Combined extensibility acceptance (E01)

E01 passes on the development host from a fresh build. This checkpoint adds shared
acceptance fixtures, Collector proof and measurements; it changes no runtime code.
The release executable is byte-identical to verified C3.24.

## Verification and limitations

- Workspace Rust: 308 passed, twelve ignored. Explicit factory three, child admission
  eight, and E01 embedding one (all three variants) passed. Four of these explicit
  tests are otherwise ignored: 312 distinct passing Rust tests; eight pre-existing
  ignored cases remain unrun.
- Full Node: 280 passed. Project tests: 34 passed. TypeScript, warnings-denied
  all-target Clippy, formatting/diff, debug and release binary/example builds passed.
- [Collector proof](c3.25-collector.json) passed. The initial expected count omitted
  four validation spans; the corrected gate verifies their attribution explicitly.
  [Progress evidence](c3.25-progress.md) retains that initial fixture failure.
- [Live proof](c3.25-live.json): OpenRouter `z-ai/glm-5.3-flash` CLI/ACP passed in
  approximately 2.18/1.64 seconds; Vercel `zai/glm-5.3-flash` ACP passed in 2.45
  seconds. Every task admitted exactly two model calls and one `fs.read`; no shell
  ran. Only the executable opened the selected root dotenv reference. Raw traces
  remain ignored and temporary task workspaces were removed. These bounded paid
  checks refresh [C3.7 OpenRouter proof](c3.7.md) and explicit Vercel compatibility
  after the intervening lifecycle additions; they do not claim live combined E01
  behavior or remote-provider latency distributions.

The assessed capability is a local depth-one child tree with owned, narrowed MCP/
Skill/native tools, selected schema-valid results and workspace revision checks,
and continued execution after basic compaction. The development host is macOS
arm64 with Node 24.11.0 (repository pin 24.20). This does not satisfy the four native
release-target gates, A2A, persistent agents, graph scheduling, artifact snapshots
or concurrent-write isolation. Those remain at their selected checkpoints. The
prior F03 notification-count recurrence remains C3.33; passing this suite is not a
claim that it was fixed.

## Performance

All measurements ran sequentially after tests, builds and live checks finished.
[Matched saved C3.24/current controls](c3.25-measurements.json) use byte-identical
executables, with source/binary/harness parity checked. Baseline/current medians in
ms: core 9.142/9.121; ACP initialize 11.041/11.391; fresh prompt 16.257/16.597;
warm prompt 14.457/15.017. Warm RSS: 18,592/18,480 KiB. Filesystem read/list/search/
replace/edit medians: 0.135/0.134, 0.987/0.980, 2.056/2.053, 0.510/0.508,
0.458/0.440 ms. These small mixed differences establish no code speedup.

The [combined E01 baseline](c3.25-extensibility-measurements.json) measures complete
fresh ACP startup, independent Python MCP startup, Skill activation/read, child
fan-out/fan-in, forced overflow/compaction, validated handoffs, native trace and joined
shutdown. Thirty samples plus five warm-ups: median 265.866 ms, p95 276.034 ms.
Each run makes seventeen model and eleven tool calls. Context after compaction was
22.858% of its previous size, while the tested task/capability/ownership invariants
remained true. Fixture setup/verification are excluded. This is a workload baseline,
not isolated compaction overhead or live-provider timing.
