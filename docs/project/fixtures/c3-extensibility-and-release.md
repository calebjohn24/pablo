# C3 acceptance fixture map

These examples define required observations for [cycle C3](../cycles/003-extensibility-and-release.md). They are initially unexecuted specifications, not new tests or completion evidence. Freeze exact wire examples, expected outcomes, bounds and an executable command in the owning checkpoint before implementation, following the [contract map](../contracts/c3-extensibility-and-release.md). Extend the cases deliberately with actual failure findings; retain the original intent and explain expectation changes in evidence.

## Common fixture rules

Use private temporary directories, newly generated synthetic evidence and synthetic credentials. Reference MCP/A2A servers must use an independent pinned implementation/schema, not merely echo Pablo's serializer. Open Responses fixtures use the pinned schema/acceptance revision. Ordinary CI does not load `.env` or make paid provider calls.

For each runnable case, assert actual provider/tool/peer input and result, applicable policy decision IDs, bounded allocations/work/output, ordered events with agent identity, exactly one terminal result, accounting settlement, cancellation and joined owned cleanup. Exercise core plus the CLI/ACP surface where the checkpoint names them. Prove default trace/OTel redaction with sentinels; full synthetic traces remain ignored local evidence. Failure cases cannot create authority or hide possibly delivered work.

Every feature's fixture also proves equivalent behavior from its deployment-file options and permitted direct host settings, including effective-value provenance and the config fingerprint. The [deployment design](../contracts/c3-deployment-config.md) defines the shared contract; G04 combines all implemented areas before release.

Stable IDs identify fixture families, not test counts. A family may require several executable cases; checkpoint evidence reports actual counts. Small configured limits make races and exhaustion deterministic without changing product defaults.

## Evidence handoff

Each implementation checkpoint records its executed fixture families, concrete commands, result counts, source/build/profile versions, sanitized evidence paths and remaining platform gates. Contract-only checkpoints record schema/example/source review and leave execution claims unmade. C3.25 combines extensibility evidence; C3.35–C3.38 require current native release-candidate evidence; C3.39 publishes comparable measurements; C3.40 requires actual distribution verification. Reuse evidence only with demonstrated source/build/fixture parity and repeat affected gates after changes.
